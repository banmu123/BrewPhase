# Experiment E 交付物④：Product Eval v1 规范（冻结评测集 + 三层计分）

> 依据：GPT Q4 裁定（三层计分结构 + 门线草案 + 分母/通过/失败报告格式 + 冻结后不得
> 调门线）+ Q2 裁定（开发集 ≠ 验收集）。v0.1 草案，评测集冻结前 GPT 最终确认门线。
> **本评测集只用于正式验收**：不参与基座挑选、不参与训练、不用于调参。

## 一、集合结构与规模

| 子集 | 数量 | 用途 |
|---|---|---|
| 新增产品评测案例 | **80** | 正式验收（Q4 三层计分） |
| C/D 历史 20 题（治理 10 + 自然度 10） | 20 | 回归套件：事实回归维度不得劣于基线（Q4/Q2 裁定保留） |
| **合计** | **100** | — |

新增 80 案例的四类行为配比（覆盖过酸、过苦、萃取异常、风味描述、器具差异场景）：

| 类别 | 数量 | 案例要求 |
|---|---|---|
| E-a 应追问 | 24 | 场景预埋 1 个缺失关键变量；金标准 = {action: clarify, expected_variable: X} |
| E-b 应直答 | 24 | 信息完整；金标准 = {action: answer}；**误追问即失败** |
| E-c 补充接续 | 16 | 两轮：首轮追问 → 用户补充 → 接续回答；金标准含接续正文要求 |
| E-d 跳过处置 | 8 | 追问 → 用户跳过 → 有边界建议；含 2 例健康边界（走现行 boundary 话术） |
| E-e 特殊防护 | 8 | 多变量问题、越界请求、伪标准诱导（对照 C/D gov 题教训） |

### 案例格式（预埋金标准）

```json
{
  "case_id": "pe1-a013",
  "category": "E-a",
  "scenario": "用户：我的手冲最近又苦又涩，怎么办？",
  "gold": {
    "action": "clarify",
    "expected_variables": ["brew_method", "grind_size"],
    "prohibited": ["spontaneous_recipe", "medical_advice"],
    "followup_user_reply": "V60，中细研磨，15g/225g，92度",
    "continuation_gold": "answer，正文应引用补充参数并落到研磨或水温方向"
  },
  "fact_anchors": ["claim.pourover.v60-official-tuning"]
}
```

E-c/E-d 的「用户补充/跳过」话术**预埋在案例里**——评测时的多轮由脚本按剧本回放，保证所有模型考同一张卷。

## 二、三层计分实现

### L1 决策与多轮行为（脚本机械判分）

| 指标 | 定义 | 分母 |
|---|---|---|
| 正确追问率 | clarify 且 variable ∈ expected_variables | E-a 全部（24） |
| 误追问率 | 应直答案例中输出 clarify | E-b 全部（24） |
| 变量相符率 | 选中的 variable 在该案例 applicable_methods 内且 ∈ expected | 全部 clarify 输出 |
| 接续成功率 | E-c 第二轮决策=answer 且正文引用补充参数 | E-c 全部（16） |
| 跳过处置正确率 | E-d 输出为有边界建议（无编造、无继续追问同一变量） | E-d 全部（8） |
| 结构合法率 | 决策 JSON 可解析 + schema/注册表校验通过 | 全部 100 |

判分器只对照预埋标签，**不比较问题文本的逐字相似**（GPT Q4：不要求模型逐字输出与标准答案相同的问题；`question` 文本由注册表模板渲染后天然一致）。

### L2 事实与来源 grounding（脚本 + 人工）

- 脚本：正文引用的每个 claim 存在于知识库、来源授权覆盖用途、与案例 `fact_anchors` 不冲突；未标注 claim 的事实句清单（供人工核查）。
- 人工：抽样核查证据是否真支持该句；**严重事实编造 = 0 项** 是硬门线（C/D 教训：nat_q7 机理编造、gov_q8 香精链均为失败判例）。

### L3 自然度与表达（裁判模型 + 人工抽检）

- 固定裁判模型、版本、评分 prompt、推理参数，**隐藏被测模型身份**；20 分制。
- 至少 20% 案例分层人工抽检；裁判与人评分歧 ≥2 分或出现可疑事实 → 升级人工复核，裁判不单独定夺。

## 三、门线（GPT Q4 裁定草案，评测集冻结时最终确认）

| 指标 | 门线 |
|---|---|
| 正确追问率（E-a） | ≥ 85% |
| 误追问率（E-b） | ≤ 10% |
| 接续成功率（E-c） | ≥ 85% |
| 跳过处置正确率（E-d） | ≥ 90% |
| 严重事实编造 | 0 项 |
| 自然度（20 分制） | 相对同策略基座下降 ≤ 1 |
| C/D 20 题回归 | 不复现两项历史错误；行为分不低于 7/10 口径的对应维度 |

**报告格式（强制）**：每项指标列出分母、通过数、失败数、失败案例 id 清单——杜绝 C/D 的总分算术问题；任何项无分母不得通过。

## 四、运行协议

1. 被测对象：候选基座零样本（Q2 开发集另设）+ E1/E2 适配器 + 对照基线。
2. 推理参数：决策调用与正文调用均 greedy（temp=0），与 C/D 评测同口径；端到端延迟按 E-7a 两段式分别计时（决策延迟 + 正文延迟）。
3. 输入策略冻结：system + 显式 ChatML（沿用 C/D 评测的 tokenizer 交叉校验做法）。
4. **冻结流程**：案例与门线由负责人确认 → 提交 GPT → 打 tag（`product-eval-v1`）→ 任何修改需要新版本号并说明理由；评测集冻结后不得按模型结果调门线。
5. 产物：`/tmp` 生成原始回答 → 全量入库 `experiment_E_design/eval_artifacts/`（含 SHA256 清单），可远程审计（C/D 审计包惯例）。
