## 一、候选与角色（Q2 裁定）

| 候选 | 角色 | 筛选关注 |
|---|---|---|
| Qwen2.5-3B-Instruct 4-bit | 历史对照 | 与 C/D 记录衔接（同基座基线可直接对照）；不默认作产品基座 |
| Qwen3-4B 4-bit MLX | 主候选 | 行为判断、多轮指令遵循、运行成本的综合最优 |
| 7B 级 4-bit MLX | 能力上限候选 | 额外容量是否换来足够行为收益；内存/延迟代价 |

## 二、筛选开发集（与 Product Eval v1 分离）

- 独立小型开发集 **~30 案例**（从 ①注册表 12 变量 × 场景矩阵抽取，含应追问/应直答
  两类各半；与 Product Eval v1 的 80 案例**零重叠**，案例 id 空间隔离 `dev-` vs `pe1-`）。
- 只支持零样本推理评测（Q2 边界）：各候选以同一决策 prompt 模板（①的 system 模板）
  生成决策 JSON，按 L1 机械判分（合法率/正确追问/误追问/变量相符）+ 简易事实抽查。
- 排序规则（**字典序，跑分前锁定，跑分后不得调整**）：
  1. 入场线：结构合法率 ≥ 95%；
  2. 最低门槛：正确追问率 ≥ 70% **且** 误追问率 ≤ 15%（任一不达即淘汰——防「从不
     追问」模型凭低误追问率胜出）；
  3. 通过门槛者按字典序排序：误追问率升序 → 正确追问率降序 → 端侧内存成本升序。
- **生成模式一致性**：候选若为 Qwen3 系，思考模式（thinking on/off）与输出模板在
  开发集筛选与最终运行时**显式设定一致**，否则 JSON 合法率比较混入生成模式差异。

## 三、许可证核验（Q2 明确的前置项）

- **核验对象是实际下载/转换/分发的具体模型与量化版本**，不是模型名：
  - Qwen2.5-3B-Instruct → 上游标注 **qwen-research**（非 Apache）——若入选需单独评估
    分发约束（端侧内嵌权重 = 分发行为）；
  - Qwen3-4B / Qwen2.5-7B-Instruct → 上游标注 **Apache-2.0**（仍以实际 HF 模型卡为准）；
  - 量化版本（MLX 社区 4bit）可能是第三方转换——需核验转换库的许可与来源说明。
- 核验结论写入本文件的「核验记录」节后才允许进入正式选型；**下载仅限开发集零样本
  评测所需**（Q2：不含下载豁免、不含训练授权）。

## 四、决策流程

```
许可证核验记录 → 开发集三候选零样本跑分 → 排序 → 负责人选定 → GPT 确认
  → 冻结单一基座进 E1（其余候选不再训练）
```
