**审核记录数据模型**：要求两名独立人工审核者，但核心字段仍是单一 reviewed_by/reviewed_at——无法记录两人各自结论、时间与负责人裁定。改为**数组结构**（每审核者独立身份/结论/时间戳，负责人裁定独立字段）。「流程要求双人审核」必须在数据中留下可审计证据。

### 2. E2 训练记录缺少实际的 RAG 证据输入（v0.2 最重要的技术问题之一）

正文调用不携带决策 JSON 正确；但回答记录只有任务模板和对话历史，**没有 RAG 检索证据**——训练时模型只从用户历史学答题，运行时却额外收到 RAG 事实，分布不一致，模型会更依赖参数化记忆而非「按提供的证据回答」。

**正确做法：RAG 证据作为独立、明确标记的模型可见输入。** 回答记录逻辑结构：
1. 回答任务指令（纯正文、F/P/I 分层、claim 来源约束）
2. 用户可见对话历史（原始问题、渲染后追问、补充信息；不含决策 JSON）
3. **独立检索证据块**：RAG 提供的已授权事实内容 + 来源标识；模型可见但非用户对话历史
4. 目标序列：纯自然语言正文，与 App 实际推理提示布局一致

**训练记录必须与 App 真正传入模型的提示格式一致；若线上检索证据的注入位置、格式与上下文顺序尚未确定，回答记录模板就不能冻结。**

### 3. Claim 授权核验还没落实到全部训练候选

对照 source_exceptions.json 与 SOURCE_REGISTRY.json，注册表多个 training-candidate 不在对应授权清单内：

| 注册表候选 | 当前发现 | 处理要求 |
|---|---|---|
| claim.espresso.fellow-ratio-example | fellow-brew-talks 例外允许的是 fellow-ratio-1to3 等，不含它 | 替换为已获准 claim 或完成新授权审批 |
| claim.espresso.fellow-dose-tamp | 不在 fellow-espresso-basics 允许清单 | 未核准前不得作训练候选 |
| claim.espresso.linea-micra-yield | 来源许可商业用途不明、衍生不允许；无对应例外 | 取得授权或移出训练候选 |
| claim.water.sage-no-bottled / sage-no-distilled / scale-mechanism | Sage 来源未出现在可用 claim 例外清单 | 先解决来源与 claim 准入 |
| claim.extraction.ucdavis-brewing-chart | 引用的是 ucdavis-research-index；不能用 ucdavis-coffee-center 的例外替代 | 按实际 source ID 单独核验 |
| claim.grinding.aeropress-grind-ref、claim.cleaning.parts-diagram | 不在对应允许 claim 清单 | 不得直接视为已获准 |

另：water_source 当前引用的 Sage claim 讨论的是**除垢时**对瓶装/蒸馏水的限制，不能直接证明该变量对普通冲煮风味诊断的作用——即便未来获授权仍需核事实支持。

**要求**：生成轨迹前为每条 training-candidate 建立完整核验表（claim_id、source_id、适用器具、证据支持范围、deployment_purpose、授权记录、最终准入状态）；未通过的标 **blocked 或 design-only**，不得进入训练素材生成。当前授权仅覆盖明确批准的非商业研究用途；商业端侧分发的限制（v0.2 写法正确）必须保留。

### 4. E1 阶段闸门还缺事实回归条件

E1 过关条件应明确为：
1. E1 阶段验证集四项决策指标全部过线；
2. **单独通过 C/D 历史回归套件的事实与行为检查**，不复现已知重大事实错误（E1 只训练 JSON 也可能影响同一适配器的回答行为）；
3. **使用现有 RAG 回答链路检查 E1 适配后的回答行为**——这不是 Product Eval v1，也不能据此调整最终验收集。

E1 端到端预检保留为可选观察，但**不能用「可选参考、不计门线」替代事实回归闸门**。

另：e1s 一处禁止「调参迭代反馈循环」、一处允许「失败后修订下一版」——需明确：若基于 e1s 结果改变后续实验，下一次实验应使用**新版本的独立阶段验证集**，或以未冻结开发集诊断；不得把同一冻结集反复调试还称其为独立验证集。

### 5. Product Eval v1 还缺两项计分定义

- **L3 自然度门线写入主规范**：相对同策略基座下降 ≤ 1/20，并定义基准模型、聚合方式与配对评分口径——不能只隐含在 README 旧速查里。
- **E-e 分项分母**：该类含多变量问题、越界请求、伪标准诱导，不等于全部 8 例都须拒绝。按每案例实际目的分别定义医疗边界/伪标准/无依据因果/拒绝转介的分母与通过标准；正确拒绝率只对确实需要拒绝或转介的案例计算，不把合理回答误判为错误拒绝。

## 二、其余项目评价

- ② 开发集排序逻辑通过；门线建议同时写实际通过数（如合法率至少 29/30；两类各 15 例则正确追问 ≥11/15、误追问 ≤2/15）。
- ⑦ 行为一致性验收与真机实测原则通过；**端侧权重商业分发授权仍是独立发布阻断项**，不因非商业研究训练获准而自动解决。
- LLMs-from-scratch 映射无新问题；MLX-LM 官方文档为实施规范唯一权威的做法保留。
