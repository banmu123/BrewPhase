## Q1. 决策输出格式：批准结构化 JSON，解析失败安全降级

裁定：采用机器可读 JSON，不采用自然语言决策句，也不需要额外的 XML 标签。

模型必须先判断本轮应当追问还是直接回答。这个输出是供程序使用的内部协议，不是直接展示给用户的回答。

建议第一版固定成下面的结构：

```json
{
  "schema_version": "1",
  "action": "clarify",
  "missing_variable_id": "grind_size",
  "question": "这杯咖啡的研磨度大概是多少？",
  "reason_code": "insufficient_diagnostic_information"
}
```

当信息已经足够时，模型输出 action: "answer"，并将 missing_variable_id 和 question 设为 null。程序收到这个决策后，进入现有 RAG 检索和回答链路，而不是让模型在决策 JSON 中直接编写最终咖啡答案。

三个实现要求：

1. missing_variable_id 必须来自受控变量枚举，不能让模型自由编造字段名称。
2. 只有当 action、变量 ID 和问题文本通过校验后，程序才呈现追问。
3. JSON 无法解析、字段不合法或输出为空时，采用 fail-closed 降级策略：不执行未经校验的追问，回到现有的一问一答 RAG 流程，给出有边界的建议；记录异常，但不得导致 App 崩溃或空白。

配置层只放策略阈值和开关；建议将变量定义建成独立的类型或注册表，而不是把所有逻辑都塞进 IntelligenceConfig。

## Q2. 基座选择：批准 2–3 个候选做零样本筛选，再冻结单一基座

裁定：允许候选基线比较，但不得在三个基座上同时开展微调。

| 候选 | 角色 | 主要考虑 |
|---|---|---|
| Qwen2.5-3B-Instruct 4-bit | 历史对照 | 能与 C/D 的历史记录衔接，但不默认作为新产品基座 |
| Qwen3-4B 4-bit MLX | 主候选 | 规模适中，优先考察行为判断、多轮指令遵循和运行成本 |
| 7B 级 4-bit MLX 模型 | 能力上限候选 | 评估额外模型容量能否带来足够的行为收益，同时测量内存和延迟 |

一个容易忽略的限制：目前公开模型卡对不同候选声明的许可证并不相同。Qwen2.5-3B-Instruct 标注 qwen-research，而 Qwen3-4B 与 Qwen2.5-7B-Instruct 的上游模型卡标注 Apache-2.0。正式选型前仍必须核验将实际下载、转换和分发的具体模型及量化版本的许可证，不能只看模型名称。

实验设计原则：**用于挑选基座的开发集，不能再充当最后的独立验收集。**

- 基座选择开发集：用于比较 2–3 个候选的零样本能力。
- 独立产品评测集：60–100 个冻结案例，只用于正式验收，不参与基座挑选或训练。
- 另保留 C/D 原来的 20 题作为回归套件。最终只能选择一个基座进入 E1。

这项裁定仅允许做零样本推理评测，不包含模型下载许可豁免，更不包含训练授权。

## Q3. 数据授权与审核：采用轻粒度 synthetic 标记，但事实必须可追溯

裁定：选择方案②，但加强事实追溯要求。**审核 rubric 由我（GPT）提供第一版框架，你方负责落成仓库文档，再交我复核。**

不要求每个自然语言句子都机械地绑定一个来源，但必须做到：每条可核验的咖啡事实，都能追溯到已批准、且授权范围覆盖当前用途的 claim。

每条轨迹最少记录以下元数据：

| 字段 | 要求 |
|---|---|
| trace_id、behavior_class | 唯一标识及 A/B/C/D 行为类别 |
| synthetic_scenario | 用户场景、冲煮参数等是否为合成内容 |
| claim_ids | 助手回答实际使用的已授权事实 |
| interaction_skill | 主动澄清、直接回答、跳过处理等行为标签 |
| review_status、reviewed_by、reviewed_at | 人工审核记录 |
| split_group_id | 防止同一场景的近似轨迹跨集合泄漏 |

合成场景中的「用户说这杯冲了 35 秒」是构造出来的案例条件，不需要伪装成真实采集事实；但如果助手据此讲述咖啡萃取机理，就必须使用有来源依据的 claim。实践建议（P）与明确标注的推断（I）也要保留原来的语义区分。

**样本获批不等于无限制授权。** 原来源授权范围不能因为新建 E 数据集而自动扩张。正式生成数据前，必须核对 claim、样本用途、具体模型许可证，以及将来产品商业化所需的授权边界。

GPT 提供的第一版人工审核 rubric 六个检查门：

1. 来源、claim 和使用目的授权合规。
2. 多轮轨迹完整，上一轮回答能被下一轮正确接续。
3. 追问是否必要，是否只问一个关键问题。
4. 用户补充、跳过后，助手是否作出正确响应。
5. 所有可核验事实有依据，推断及实践建议没有冒充事实。
6. 文本自然、没有重复模板、隐私泄露或越界建议。

你方负责将它转换成实际的数据审核文档与机器可检查字段，GPT 复核最终版本。AI 生成只负责扩展场景，不能取代逐条人工审核。

## Q4. 评测计分：接受三层结构，但增加明确门线和复算规则

裁定：接受三层计分结构。不允许用一个综合分数掩盖主动追问失败或事实错误。

**第一层：决策与多轮行为**——以案例预埋的标准标签机械评分，而不是要求模型逐字输出与标准答案相同的问题：
- 该追问的案例：正确追问率
- 应直答的案例：误追问率
- 用户补充后：接续成功率
- 用户跳过后：正确降级率
- 追问变量是否与该场景的允许变量相符

**第二层：事实与来源 grounding**——脚本验证事实引用的 claim 是否存在、是否授权、是否在目标消息中声明使用；人工检查证据是否真的支持该回答。尤其不能重复 C/D 的重大事实回归。

**第三层：自然度与表达质量**——固定裁判模型、版本、评分 prompt 和推理参数；隐藏模型身份进行评价，并对至少 20% 的案例做分层人工抽检。出现严重分歧或可疑事实时，升级为人工复核，不能让裁判模型单独定夺。

Product Eval v1 门线草案（待设计文件确认、评测集冻结后不得按模型结果调整）：

| 指标 | 建议门线 |
|---|---|
| 应追问案例的正确追问率 | ≥ 85% |
| 应直答案例的误追问率 | ≤ 10% |
| 用户补充后接续成功率 | ≥ 85% |
| 用户跳过后的正确处理率 | ≥ 90% |
| 严重事实编造 | 0 项 |
| 自然度 | 相对同策略基座下降不超过 1/20 |

报告必须列出各项分母、通过数和失败数，以避免 C/D 出现的总分算术问题再次发生。

## Q5. 训练分期：采用 E1 → E2，不一步到位联合训练

裁定：接受两阶段训练方案，但 E1、E2 各自设门槛，**E1 达标不自动获得 E2 训练授权**。

**E1：结构化决策行为**——验证新假设：模型能否根据当前问题与可用上下文，输出符合 schema 的 answer 或 clarify 决策，并选中合理的缺失变量。只训练决策目标，数据同时包含应追问和应直答的例子。评测重点是正确追问、误追问、变量选择、结构化输出合法率，以及事实回归。只有在独立评测达标、重大事实回归为零之后，才申请 E2。

**E2：完整多轮行为与回答质量**——在 E1 达标的前提下，训练并评估完整的「追问 → 补充信息 → 接续回答」及「追问 → 用户跳过 → 有边界地回答」等轨迹，同时保留直答和特殊防护案例。若从 E1 适配器继续训练，必须使用独立的 E2 输出路径，保留 E1 产物用于回退和比较。E2 还要重新评估是否引入事实退化、自然度损失或过度追问。

两个阶段是把实验假设拆开：先验证模型能否学会决策，再验证完整多轮行为是否可靠——失败时可归因到决策学习还是多轮回答，而不是像 C/D 一样难以归因。

**当前不执行 E1 训练。** 先完成基座筛选设计、rubric、完整训练样本、独立评测集和 App 运行方案，再提交正式训练审批。

## Q6. 旧 43 条数据：选择性复用，不整批搬入

裁定：接受「六条单轮 clarification 不并入 E 训练集」的建议；其余样本只做选择性复用。

- 六条旧 clarification 样本：不作为 E1/E2 的训练目标（缺乏完整的多轮接续或跳过轨迹，不能代表新行为任务）。保持原有 approved 记录不变，不删除、不降级。
- Batch2e 的四条直答样本 b2e-005 至 b2e-008：可以作为 C 类直答或与语义相符的特殊防护示例候选，但必须复核标签、事实依据和授权字段。
- 其他旧 approved 样本：不批量原样导入。只有行为分类清晰、claim 授权有效、回答质量合格、符合 E1 或 E2 任务格式，才允许转换后进入 E 的新数据版本。

不能为了凑足 300–500 条轨迹而把 43 条旧数据直接拼接进去。新的 E 数据集应有独立版本、明确的来源映射、去重与分组划分，以及单独的训练准入检查。原始数据和 C/D 历史版本均保持不变。
