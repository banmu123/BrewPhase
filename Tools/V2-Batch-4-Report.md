## 2. Bean Detail 最终信息层级

第三批已按 `Hero → 阶段 → 库存 → 最近一杯 → [记一杯] → 冲煮记录 → 风味变化 → 预计风味窗口 → 知识 → 问一问 → 备注` 完成，本批复核无回归；Hero 保持三信息焦点（名称 / 烘焙度 / 第 N 天），照片只是 54pt 缩略图辅助，不占首屏。

## 3. Quick Log 最终操作路径

默认路径 3 次点击：确认豆（自动预选）→ 点评分 → [记下这一杯]。本批新增：

- **参数变化轻量化**：`这次改了` 里数值参数现在显示「快 22 秒 / 高 1°C」（复用 `BrewDelta.Change.phrase`），文本参数才退回 `2:15 → 2:28`。
- **连续记录**（`logAnother`）复核确认：保留同一包豆与器具、以刚存下的这杯重新预填——第二杯比第一杯更快。
- **首次引导**：第一次成功保存后结果页出现一行「下次记这一杯，会自动带上这次的参数。」（UserDefaults `PrefKey.didShowPrefillHint`，只出现一次）。

## 4. Insights 最终结构

`今天喝哪包 → 手冲还是意式 → 最近一杯（与上一次相比）→ 我的最佳参数 → 下一步`。本批：

- **豆子切换器回归**：第二批重构时 `beanPicker` 成了死代码（用户无法换豆）；现在挂在「最近一杯」标题右侧，多于一包时出现。
- **数据不足状态**（规格 §十六）：不再显示冷冰冰的「证据不足」标签，改为「还在认识你的冲煮习惯 / 再记录几杯，这里会开始出现你的个人规律。」+ 证据行里的真实计数。
- **历史规律定性**：「我的最佳参数」下方固定一行「这是你自己的高分记录统计，不是专业标准。」
- 复核确认用户语言无 AI/模型/RAG/嵌入/引擎词汇（全项目仅剩高级设置里一处「检索方式」，属规格允许的高级语境）。

## 6. Empty / Loading / Error / Success 状态清单

- **空**：首页空豆仓、首页全喝完、首页有豆无 brew、Insights 空库、Insights 数据不足、最近一杯无记录、时间线空态、Quick Log 无豆、Ask 空会话。
- **错误**：所有保存路径（第一批已统一：保留编辑状态 + 明示失败）；删除失败 alert。
