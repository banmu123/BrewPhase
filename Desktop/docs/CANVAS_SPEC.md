# 画布规格

参考 Sublime Web Canvas 的**空间感**，不照搬它的视觉资产，也不做流程图/白板工具。

## 1. 坐标

```
screen = world × scale + offset
world  = (screen − offset) ÷ scale
```

- 节点只存**世界坐标**；平移/缩放只改视口（`CanvasViewport`），节点数据不动。
- 换算只有一处：`src/shared/contracts/entities/canvas.ts` 的 `worldToScreen` /
  `screenToWorld` / `zoomAt`。禁止在组件里重写公式。
- 缩放围绕指针位置（wheel）或画布中心（按钮），范围 0.2–3。

## 2. 交互（Phase 1 实现）

| 操作 | 行为 |
| --- | --- |
| 空白处按住拖动 | 平移画布（只改 offset） |
| 滚轮 | 以指针为锚缩放 |
| 拖动节点 | 只改渲染层位置；**松手写一次库** |
| 点击节点 | 选中（描边 + 阴影），右侧显示世界坐标 |
| 右侧「从记录添加」 | 新建节点，自动找不重叠的位置 |
| 移除节点 | 只解除引用，记录仍在 |
| 删除画布 | 节点级联删除，记录不受影响 |

## 3. 落位

`nextNodeOrigin` 逐行扫描：从当前起点开始，按「节点宽/高 + 间距」排布，命中已有
节点就跳过。**不做自动排版**——用户摆的位置永远优先，这里只负责「新卡片不要
叠在别人身上」。

## 4. 节点渲染

四类节点共享同一套工作台语言（`--canvas-node` 纸面、14px 圆角、1px
`--canvas-rule` 边界、espresso 选中细描边），内部结构按载体各自成立：

| 载体 | 渲染 |
| --- | --- |
| image | 本地展示图（`bpmedia://`）出血铺满，无边框；底部渐隐压标题；读不到退回占位卡 |
| video | 同图片 + 标题上方一行 9px「视频」类型标签；播放按钮是独立命中区（浅底深字，不随主题翻转） |
| link | 封面（无图则域名首字兜底）→ 来源行（latte 小点 + 域名）→ 标题 → 摘要 → 底部备注（细竖线引文） |
| text | 无图无来源，靠排版站住：顶部 espresso 短线起头、标题 1.45 / 正文 1.65 行距、底部细线 + 备注 |

规则：

- 来源标识**只有一种**：小圆点 + 域名。不做彩色徽章——每张卡一种颜色的话，
  颜色就失去意义。
- 备注是一段「贴上去的便条」：斜体、比正文小一号、左侧细竖线。
- 选中 = espresso 1.5px 描边 + 右下角 espresso 角柄。**sage 只表达业务状态**
  （阶段、库存），不用于选中。
- 便签纸色是用户数据，不随主题翻转；纸上的字永远用墨水色
  （`--media-control-ink` 同值），否则深色下浅黄纸上会出现白字。
- 压在封面上的文字用 `--media-ink / --media-scrim`（深浅两套同值）：
  图片自己会亮，这层不能跟着主题翻。
- 只读本地缓存：不创建 `AVPlayer`/`<video>`、不请求网络、不建 WebView。

## 5. 手绘（表已建，工具未做）

`canvas_strokes` 存：`tool_type`（pen/eraser）、`points`（**世界坐标** `[x0,y0,x1,y1,…]`）、
`color`、`width`、`opacity`、`z_index`。

- 落库前必须先把屏幕点换算成世界点，否则缩放后笔迹会跑。
- 撤销/重做、橡皮擦、笔刷面板在 Phase 4。
- **iOS 端目前没有对应模型与渲染**：这一版不能声称两端都能看到笔迹。

## 5.5 关系线（本阶段只有视觉规范，没有实现）

**当前事实：数据库里没有任何关系持久化模型。** `canvas_nodes` 只有位置与尺寸，
没有 edges/connections 表；`workContextResources` 是工作上下文的资源关联，
不是节点间关系。因此本阶段**不画任何线**——在 Konva 里画一条存不下来的线，
就是把装饰冒充成功能。

视觉规范（实现时按这个来）：

| 关系类型 | 语义 | 视觉 |
| --- | --- | --- |
| Reference | 引用、参考 | 细实线 1px、两端小圆点、低存在感 |
| Inspiration | 灵感启发 | 柔和 Bézier、轻虚线（2-3 短横）、无端点 |
| Practice | 从内容到实际行动 | 曲线 + 箭头端点（唯一允许箭头的类型） |
| Evidence | 实践结果或证据 | 实线 + 中点小方块（像图钉） |

- 一律 Bézier 曲线，不走直线；颜色用 `--canvas-dot` 到 `--ink-faint` 之间，
  hover / 选中才提到 `--espresso`。
- **用户确认的关系是实线；AI 提议的关系是低亮度虚线 + 空心端点。**
  AI 不能把提议转成正线——这条边界和 `direction:propose` 一样，是通道层面的
  事实，不是提示词约束。
- 线的语义存在哪、由谁确认、删除节点时线怎么处理——都需要在实现前先建表。
  真做的时候涉及：新表 + 迁移、Repository、Service、iOS 同步实体、
  MCP 读写契约与 scope、Konva 渲染层与命中检测。这是一整个独立阶段。

## 6. 后续（不在本阶段）

连接线、分组区域、框选与多选、图层管理、图片直接拖入、导出。

## 7. 验收（本阶段）

1. 新建画布 → 从记录添加 4 种载体 → 都能显示。
2. 拖动节点 → 关掉应用重开 → 位置不变。
3. 滚轮缩放、拖动空白平移 → 节点相对关系不乱。
4. 移除节点 → 记录仍在；删记录 → 节点消失。
