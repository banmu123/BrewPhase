# BrewPhase 真机同步联调指南（iPhone ↔ Mac）

面向操作者本人。目标：一次走通 **扫码配对 → 首次同步 → 媒体传输 → 增量同步 → 冲突裁决 → 撤销设备**。

## 0. 环境准备

- Mac 运行 BrewPhase Desktop（开发模式：`cd Desktop && npm run dev`；真机联调必须用这份，测试构建的数据库是独立的）。
- iPhone 安装相同代码构建的 BrewPhase（Xcode 直接 Run 到真机）。
- 两台设备连**同一个可信 Wi-Fi**；**暂时关闭 VPN**（utun 接口会被二维码降权，但开启 VPN 可能导致手机到 Mac 的直连被劫持）。
- macOS 防火墙若开启：系统设置 → 网络 → 防火墙，允许 BrewPhase 接收入站（或临时关闭验证）。
- iPhone 首次同步会触发**本地网络权限**弹窗，必须允许（设置 → 隐私与安全性 → 本地网络）。
- 相机权限：首次扫码会弹窗，允许。

## 1. 扫码配对

1. Mac：BrewPhase Desktop → **更多 → 设备同步 → 启用局域网同步**。
2. 确认状态行显示「运行中 · 端口 47821 · <局域网 IP>」。若显示「服务未能启动」，换一个端口场景重试（47821 被占时自动回落，状态行显示真实端口）。
3. 点 **连接新手机** → 出现二维码 + 120 秒倒计时。
   - 若提示「未检测到局域网地址」：Mac 没有可用 Wi-Fi/网线连接，先联网。
4. iPhone：BrewPhase → **更多 → 桌面同步 → 扫描桌面端二维码**。
5. 扫码后 App 会**逐一探测二维码里的候选地址**（每候选 2 秒超时），验证通过才发起配对——配对码一次性，不会向多个地址重复兑换。
   - 全部地址连不上 → 明确报错（列出已尝试的 IP）。检查：同一 Wi-Fi？Mac 防火墙？IP 是否与 Mac 系统设置里的一致？
   - 「配对码已过期」→ Mac 上点「换一个码」重扫。
   - 「桌面端版本不兼容」→ 两端代码不一致，更新到同一版本。
6. 配对成功 → 显示「已连接桌面端」+ 本地待同步数据统计。

## 2. 首次同步

1. 阅读确认区文案（会复制什么、不会删除什么），点 **开始首次同步**。
2. 观察阶段文案：豆子 → 冲煮 → 品鉴 → 阶段规则与提醒 → 收藏记录与标签 → 画布 → 传输图片和视频（n/总数）。
3. 结果行显示：`已新增/更新 N · 内容一致 N · 冲突 N · 失败 N` + `媒体文件：图片 N · 视频 N · 失败 N`。
4. Mac 上验证：
   - **咖啡页**：豆子、冲煮、品鉴齐全，数量与 iPhone 一致。
   - **收藏页**：记录、标签筛选正确（标签关系已同步）。
   - **图片/视频**：图片能显示；视频文件在 `~/Library/Application Support/brewphase-desktop/media/`（文件名 UUID.mov/mp4），数据库 `records.media_path` 引用正确。
5. 冲突 > 0 时：Mac 设置页冲突区会列出，逐条裁决（保留电脑版本 / 接受手机版本 / 删除冲突的「接受删除」带确认）。

## 3. 增量同步与幂等

1. iPhone 上随便改一条记录/再拍一张，回桌面同步页点 **立即同步到桌面端**。
2. 确认：只有变化条目显示「已新增/更新」，其余「内容一致」；媒体清单里已有且哈希一致的文件不重传。
3. 连续同步两次，第二次应几乎全部「内容一致」且无新增冲突。

## 4. 冲突与删除语义（可手动构造）

- 桌面改一条记录（不要同步）→ iPhone 也改同一条 → iPhone 同步 → 应出现**冲突**，桌面数据保留。
- 裁决「保留电脑版本」→ iPhone 再次同步相同内容 → 直接收敛（skipped），不再产生冲突。
- iPhone 之后真实修改该记录再同步 → 重新进入合并（可能再次冲突），**不会静默覆盖**桌面数据。
- iPhone 删除一条桌面端已修改的记录 → 产生**删除冲突**；「接受删除」需二次确认并真正删除桌面行。

## 5. 撤销设备

- Mac 设置页对该设备点 **撤销授权** → iPhone 再同步应得到 401（App 提示未配对/失败）。

## 6. 常见故障速查

| 现象 | 排查 |
|---|---|
| 扫码后「无法连接桌面端」 | 同一 Wi-Fi？VPN？Mac 防火墙？二维码里的 IP 与 Mac 当前 IP 一致？（Mac 换网后需重新生成二维码） |
| 「服务返回 401: invalid pairing code」 | 码过期/已用过/桌面端重启过 → 重新生成二维码 |
| 「服务返回 429」 | 连续失败触发限速，等 60 秒再试 |
| 同步卡在媒体传输 | 看 Mac 端 `media/.incoming` 是否有残留；重试会按 offset 续传 |
| 结果里有「失败 N」 | 媒体文件本地读不到或引用缺失；详情会计入失败数，修好后再次同步自动重试 |
| 桌面端改完代码不生效 | electron-vite dev 不会热重启主进程，需重启 dev server |

## 7. 边界如实声明

- 当前为**局域网 HTTP**（无 TLS），仅在可信网络使用；TLS 是发布前独立任务。
- 未实现：Bonjour 自动发现、双向同步、云端中继。
- 模拟器 / localhost 测试不等于真机局域网验证——本指南描述的验收必须用真实双机完成。

## 11. 已知边界（验收时不要误判为失败）

- 首轮导入很多链接时按并发 2 逐条抓取，全部完成需要时间；期间显示「正在获取预览…」。
- `failed` 不会自动重试（按设计），需要手动「重新获取」。
- 视频时长/播放量没有可靠来源，卡片不展示。
- 若本机 `/etc/hosts` 被加速器改写（GitHub/YouTube 域名指向 127.0.0.1），
  元数据会全部失败并显示「暂时无法获取预览」——这是安全层的正确行为，先清 hosts。
