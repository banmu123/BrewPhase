# BrewPhase Personal Direction

## Personal + AI 产品设计规格 V0.1

**产品理念：豆有豆期，花有花期，人也是一样。**

**核心表达：Your journey, at your own pace.**

> **实现状态（Desktop V0.1 第一阶段）**
>
> 已落地：Current State / Direction / Stage Goal 三层数据、Repository、
> Application Service、4 个 MCP 工具（1 读 3 提议）、Studio Home 底部面板、
> 四步引导表单、草稿与正式资料的分离。
>
> 尚未落地：Activity History（第二阶段）、Guidance（第三阶段）、
> Forecast（第四阶段）、Desk 体验收口（第五阶段）。
>
> 与原始规格的一处实现差异：**首次引导是表单，不是聊天**。桌面端没有模型
> 调用能力，「与 WorkBuddy 的对话」发生在 WorkBuddy 客户端，它经 MCP 写草稿，
> 用户在应用内确认。所以 §9 的九步对话，在应用内呈现为四步表单，
> 每一句都由用户自己写。
>
> 另一处：MCP 侧**没有** confirm 类工具与 scope。确认只存在于 IPC，
> 只有应用界面能调——「AI 不能替用户拍板」因此是结构保证，不是约定。

## 1. 产品定位

BrewPhase 是一个 Personal + AI 个人成长与创造空间。

它帮助用户从当前真实状态出发，明确自己希望抵达的状态，通过日常行动记录、知识积累、AI Agent 协作、阶段规划与趋势预测，持续理解自己正在经历的变化，并找到下一步最值得做的事情。

BrewPhase 不负责替用户决定人生方向，而是帮助用户更清楚地认识自己的起点、目标、行动和可能的发展结果。

### 核心价值

1. 认识现在的自己。
2. 明确希望成为的样子。
3. 把长期愿景拆解为可以验证的阶段。
4. 连接日常行动、个人资料和 AI Agent。
5. 分析实际进展与目标之间的差距。
6. 预测不同路线可能产生的结果。
7. 根据变化持续调整方向。

## 2. 产品结构

Personal Direction 是 BrewPhase 的核心能力，但不新增一级导航。

继续保留现有空间：

- Coffee：咖啡、豆子、冲煮与品鉴。
- Records：收藏、知识资料与内容记录。
- Canvas：空间化组织、思考与创作。
- Browser：浏览和收集外部内容。
- Studio Home / Desk：个人方向、持续工作和 AI 协作入口。

Desk 沿用现有 Studio Home 三栏内容布局，在三栏底部逐步增加 Personal Direction 区域。

不重新实现 Records、Canvas、Browser 的已有能力。

## 3. 核心目标体系

采用四层结构：

### 3.1 Current State — 我的现状

记录用户对当前自己的真实描述。

可以包含：

- 当前工作与职业状态。
- 已有能力、经验和资源。
- 当前正在推进的事情。
- 可投入的时间与精力。
- 当前限制、困难和不满意的地方。
- 用户认为重要的其他生活或创作状态。

要求：

- 以用户主动描述为主要来源。
- 不要求首次使用时填写全部信息。
- 支持自然语言对话整理。
- WorkBuddy 可以提出补充问题。
- AI 整理出的内容必须经过用户确认才能成为正式现状。
- 允许更新，并保留重要变化的历史。

### 3.2 Desired State / Direction — 我希望成为的样子

这是用户自己定义的长期方向。

例如：

- 成为独立开发者。
- 建立自己的事业。
- 拥有可持续的收入来源。
- 获得更自主的时间安排。
- 持续创作有价值的产品和内容。

每个方向可以包含：

- Direction Title。
- Description：期望状态的自然语言描述。
- Motivation：为什么希望实现它。
- Time Horizon：期望时间范围，可以不填写。
- Observable Outcomes：能够观察和验证的结果。
- Constraints：用户明确提出的约束条件。

不强迫所有长期方向量化。

不能因为目标难以量化，就把它转化为一个没有意义的分数。

### 3.3 Stage Goals — 当前阶段目标

长期方向需要通过阶段逐渐推进。

每个阶段包含：

- 阶段名称。
- 阶段目标。
- 预期成果。
- 完成标准或验证证据。
- 当前状态。
- 预计时间范围。
- 当前障碍。
- 关联的 Work Context、Records、Canvas。

阶段状态：

- proposed：AI 或用户提出，尚未确认。
- active：当前阶段。
- paused：暂时暂停。
- completed：已完成。
- revised：经过调整。

用户拥有最终确认权。

WorkBuddy 可以提出阶段拆解和调整建议，但不能自行改变用户的长期方向或宣布重要阶段完成。

### 3.4 Work Context — 持续工作

沿用现有 Work Context V1，不重新设计重复的工作实体。

Work Context 负责保存：

- 正在做什么。
- 工作目标。
- 当前进度。
- 下一步。
- 关联 Records。
- 关联 Canvas。
- 关联 URL。

未来可以建立 Stage Goal 与 Work Context 的关联，让具体工作能够服务于当前阶段目标。

Work Context 不是 Task，也不是 Project Management Board。

## 4. Activity History — 有意义的行动历史

Activity History 是 Personal Direction 的重要基础。

它记录用户在 BrewPhase 中发生的、对目标推进有意义的行为。

### 4.1 事件来源

1. User：用户主动创建、确认或记录。
2. BrewPhase：产品内产生的业务事件。
3. Agent：WorkBuddy、Codex 等通过授权接口提交的事件。
4. Imported：用户明确授权导入的外部工作结果。

### 4.2 事件类型

- 工作开始、推进、暂停和完成。
- Record 创建或重要整理。
- Canvas 内容的重要变化。
- 阶段成果完成。
- 用户做出的重要决定。
- AI Agent 完成的研究或开发工作。
- 用户接受、调整或拒绝行动建议。
- 用户主动提交的反思和总结。

### 4.3 事件数据

建议统一包含：

- event_id。
- event_type。
- source_type。
- source_id（可选）。
- occurred_at。
- summary。
- direction_id（可选）。
- stage_id（可选）。
- work_context_id（可选）。
- related_resources。
- confirmed_by_user。

### 4.4 记录原则

不记录每一次鼠标移动、键盘输入和窗口切换。

不默认读取外部 Agent 的完整聊天历史。

不把 AI 推测的行动写成用户真实发生的行为。

优先通过 BrewPhase 已有业务操作和 MCP 授权写入有价值的活动。

用户可以查看、修正和删除活动记录，并控制外部内容导入范围。

## 5. Guidance — 自主行动引导

WorkBuddy 根据用户目标、当前阶段、工作上下文和行动历史，生成个性化行动建议。

Desk 每次优先展示：

### 当前在做

用户目前正在推进什么，以及它服务于哪个目标。

### 下一步最值得做

提供 1～3 个有明确理由的建议。

建议至少包含：

- 建议行动。
- 为什么现在应该做。
- 对应的阶段目标。
- 预期成果。
- 可能需要的时间。
- 判断依据。

### 暂时不用做

识别当前不值得优先投入的事情。

包含：

- 建议暂缓的事项。
- 暂缓原因。
- 重新评估的条件。

不能只因为一件事情暂时不重要，就将其永久删除或标记为失败。

### 用户反馈

每条建议支持：

- 接受。
- 调整。
- 暂缓。
- 拒绝。
- 标记已完成。

WorkBuddy 应根据用户反馈修正后续判断。

不允许未经用户同意就擅自修改长期方向或启动重要的新阶段。

## 6. Forecast — 趋势与结果预测

预测是 Personal Direction 的重要差异化能力。

目标不是预测用户的命运，而是帮助用户理解不同选择可能产生的结果。

### 6.1 当前趋势预测

回答：

如果用户保持当前的行动方式，可能会发生什么？

### 6.2 调整行动后的预测

回答：

如果用户改变某个关键行动，可能获得什么不同结果？

### 6.3 阶段时间预测

根据阶段完成标准、近期行动、可投入时间、实际进展和外部约束，估计完成当前阶段可能需要的时间范围。

### 6.4 风险与偏离预测

发现：

- 长期方向与当前阶段不一致。
- 日常行动没有有效推动阶段目标。
- 重要障碍长期没有解决。
- 用户投入大量精力，但关键成果缺少验证。
- 目标发生变化，而原有计划没有更新。

### 6.5 预测结果结构

每次预测至少包含：

- forecast_id。
- direction_id。
- stage_id。
- generated_at。
- evidence_window：分析使用的时间范围。
- current_trend：当前趋势。
- baseline_scenario：保持当前行动方式的可能结果。
- adjusted_scenario：调整行动后的可能结果。
- estimated_duration：预计时间范围。
- risks：风险因素。
- assumptions：关键假设。
- confidence：证据可信程度。
- recommended_adjustments：行动调整建议。

### 6.6 预测原则

1. 时间优先使用范围，不虚构精确完成日期。
2. 没有足够行动数据时，明确标记证据不足。
3. 预测必须说明数据依据和关键假设。
4. 不把 AI 主观判断包装成客观概率。
5. 不承诺用户一定能获得某个结果。
6. 重要目标或现状发生变化时重新预测。
7. 保留预测快照，允许用户比较预测和实际结果。

长期财富、职业、生活状态等目标，不能仅根据少量日常行为预测具体结果或实现日期。

## 7. WorkBuddy — Personal Direction 的主要 AI 协作者

WorkBuddy 是当前最主要的引导型 Agent。

它不是简单的待办事项生成器，而是帮助用户理解目标与现实行动之间关系的协作者。

### 工作流程

1. 读取用户确认的 Current State。
2. 读取长期 Direction。
3. 读取当前 Stage Goal。
4. 查询相关 Work Context。
5. 查看近期 Activity History。
6. 分析阶段成果与阻碍。
7. 进行趋势和情景预测。
8. 给出下一步建议。
9. 等待用户反馈。
10. 根据用户确认更新建议和工作上下文。

### 典型对话

用户：

「我感觉最近做了很多事情，但不知道是不是在接近自己的目标。」

WorkBuddy：

- 先总结用户当前目标。
- 分析近期真实行动。
- 指出哪些行动产生了有效进展。
- 指出哪些行动可能没有推动当前阶段。
- 解释按照当前趋势可能出现的结果。
- 提出最值得做的下一步。
- 询问用户是否认同。

不能在缺少数据时编造用户最近做了什么。

### Codex 与其他 Agent

Codex 负责工程执行。

其他 Agent 可以负责研究、写作、设计等具体工作。

BrewPhase 通过 MCP 提供共同的目标上下文、工作上下文和资料引用能力。

Agent 提交的工作结果需要标记来源，必要时由用户确认。

## 8. Desk 首页信息结构

继续保留现有 Coffee、Records、Canvas 三栏主体。

在底部逐步演进出 Personal Direction Panel：

1. My Direction：长期方向和当前阶段。
2. Current Activity：当前在做什么。
3. Next Best Move：下一步最值得做什么。
4. Pause For Now：暂时不用做什么。
5. Journey Forecast：当前趋势和可能的阶段变化。
6. Activity Timeline：近期重要行动。
7. WorkBuddy Conversation：围绕当前方向展开讨论。

首屏应当突出当前最重要的行动，而不是堆积统计卡片。

用户可以进一步打开详情，查看完整成长路径、预测历史和活动记录。

不新增独立的任务管理系统，不替代现有三栏空间。

## 9. 首次使用体验

首次使用不采用冗长表单。

采用与 WorkBuddy 的渐进式对话：

第一步：了解我现在的状态。

第二步：了解我希望未来变成什么样。

第三步：了解为什么这个目标对我重要。

第四步：了解现有资源、限制和可投入的时间。

第五步：WorkBuddy 汇总成 Current State 和 Desired Direction。

第六步：用户确认或修正。

第七步：WorkBuddy 提出阶段目标草案。

第八步：用户选择、修改并确认当前阶段。

第九步：生成第一版成长路径和基础预测。

用户可以跳过部分问题，之后继续补充。

不能将首次对话中的 AI 推测直接当成正式个人资料。

## 10. 隐私、授权与用户控制

- 用户始终拥有自己的目标和资料。
- 长期方向必须由用户确认。
- 用户能够随时更改、暂停或删除目标。
- AI 建议不能自动成为用户承诺。
- 外部 Agent 只获得用户授予的 MCP 权限。
- 不默认导入完整的外部聊天记录。
- 活动记录需要能够追溯来源。
- 预测必须可以查看判断依据。
- 用户可以拒绝个性化引导或关闭相关提醒。
- 不以持续打卡、排名和压力提醒驱动用户。

## 11. V1 与后续开发边界

### 第一阶段：目标体系与首次引导

- Current State。
- Desired Direction。
- Stage Goal。
- 首次使用的 WorkBuddy 对话流程。
- 用户确认和修改能力。
- 与现有 Work Context 的关联设计。

### 第二阶段：Activity History

- 有意义的行为事件。
- BrewPhase 内部事件来源。
- MCP Agent 活动来源。
- 日常行动回顾。
- 事件查看、来源追踪与用户控制。

### 第三阶段：Guidance

- 下一步最值得做。
- 暂时不用做。
- 建议依据与用户反馈。
- 与 WorkBuddy 的持续协作。

### 第四阶段：Forecast

- 当前趋势预测。
- 不同路线的情景预测。
- 阶段完成时间范围。
- 风险识别。
- 预测快照与实际结果对比。

### 第五阶段：Desk 体验完善

- 三栏底部的 Personal Direction Panel。
- 成长路径详情。
- 资源精准跳转。
- AI 协作状态和活动反馈。
- 视觉与交互收口。

每个阶段单独实现、测试和审核。不得一次性引入所有模型和功能。

## 12. 明确不做的事情

- 不做传统待办清单或完整项目管理系统。
- 不做用户人生成功分数。
- 不做强制打卡和连续使用奖励。
- 不做未经授权的桌面活动监控。
- 不做没有证据的精确预测。
- 不让 AI 替用户决定人生目标。
- 不重复实现 Records、Canvas、Browser。
- 不新增没有明确价值的一级导航。

---

## 13. 产品成功标准

BrewPhase Personal Direction 是否成功，不以用户每天创建了多少任务衡量。

更重要的是：

1. 用户能否清楚描述当前状态和想去的方向。
2. 用户能否理解自己当前所处的阶段。
3. 用户能否通过行动记录看见真实变化。
4. WorkBuddy 的建议是否有事实依据并且真正有帮助。
5. 用户是否能够理解不同路线的可能结果。
6. 用户能否主动修正自己的方向，而不是被旧计划束缚。
7. 长期使用后，用户是否更清楚自己为什么做某件事，以及下一步应该做什么。

**最终目标：让用户在自己的节奏里，持续靠近自己希望抵达的状态。**
