## Remote MCP Phase 0：P0-1 / P0-2 设计修订（用户要求，未提交）

* **P0-1 Grant 授权上下文**：A 方案（Cloud 经已认证 WSS 下发上下文）胜出，B 方案
  「每请求签名断言」被否——WSS 已双向认证，签名解决不了撤销，而撤销才是难点。
  `hello_ok.scopes` / `req.grant_id|client_id|client_name` **全部删除**（避免第二个事实来源）；
  改为 `hello_ok.grant_epoch + grants[]` / `req.grant_ctx`（必填）/ `grant_update`+`ack`；
  缓存键 `(grant_ctx, delivery_id)`；撤销 = 先停路由 → `grant_epoch+1` → `grant_update`
  → Desktop 清上下文+该 grant 缓存 → 在途回 `GRANT_REVOKED` → ack；ack 超时 fail-closed
  （暂停该设备全部 grant，协议 §6.5.2 规则 3）。权威：安全 §2.7 / 协议 §6.5。
* **两个 epoch 别混**：`grant_epoch` 设备级（帧新旧门槛，`<=当前` 丢弃）；
  `grants[].epoch` 单 grant 版本（准入第 4 步校验的是它）。
* **P0-2 `jti`**：**Token 级**，v1 不做请求级去重、不加 per-request nonce（按 jti 去重 =
  打死同一 token 的第二次正常调用 = DoS）。旧措辞（安全运维 §5.3「5 分钟重复即拒绝」、
  安全 §1 信任边界「jti + 服务端去重」）已清除。写工具开放前重评 → OQ-16（DPoP）。
* 契约计数：错误码 17→**19**、ST 17→**26**（1.1B 认领 ST-4~10/13~24，1.3 认领 ST-25/26，
  1.2 认领 ST-1~3/11/12）、OQ 22→**23**（+OQ-16；字母组 E 拆 E1/E2 故为 7 项）、
  准入链 8→**12** 步（§8.5 只列前 10）、重连清理 7→**8** 项。

## Remote MCP Phase 1.1A：共享工具执行层抽取（已实现，未提交）

* 基线实测 **949 条 / 72 文件全绿**（与历史记录一致），改后 **978 全绿**
  （949 原样 + 18 CB 验收 + 11 结构测试）。既有测试文件**零改动**。
* 新增 `src/main/application/mcp-tools/`：`tool-services.ts`（ToolServices，仅 5 个业务
  Service，无 db/clients）、`handlers.ts`（27 handler + createShape）、
  `tool-executor.ts`（`executeTool`）。`request-router.ts` 从 558 → 213 行。
* **Handler 迁移经机械比对：归一化后逐字等价**（唯一差异是 `ctx` → `services` 参数名）；
  `createShape` 同样逐字等价。27 个工具名与顺序未变。
* `executeTool(tool, rawParams, { services, scopes, replay? })` 顺序固定：
  工具白名单 → scope → Zod → replay 钩子 → handler → 错误映射。返回带 `stage`
  （'tool'|'scope'|'params'|'replay'|'handler'）与 `params`（Zod 后），**由调用方决定记账**。
* **为什么需要 replay 钩子**：Local 幂等表必须插在「Zod 通过」与「Handler 执行」之间
  （摘要要基于解析后参数；放 Zod 之前会让每次重放都退化成冲突）。幂等失效（实体已删）
  历史上不记账，靠 `stage==='replay'` 让 route 跳过审计，保持逐字一致。
* 三处**与设计文档的偏差**（未改文档，待在报告中提出）：
  1. 文档 §6.5.4 说 executeTool 返回 Remote 码（INVALID_TOOL/SCOPE_DENIED），Local 再映射；
     实现反过来（返回 Local 码 VALIDATION_ERROR/PERMISSION_DENIED），Remote 自己映射——
     这样才能保证 Local 零行为变化。
  2. 文档 §6.5.3 说 `replayIdempotent` 也搬出；实际留在 request-router.ts，
     因为它要用 `ctx.db` 查 tag（搬走会把 db 带进共享层）。
  3. 文档 ExecuteContext 有 `channel` 与 `audit`；实现都没有——`channel` 是 Remote 专用分支
     （本阶段禁止），`audit` 由调用方按 stage 决定（避免共享层依赖 audit-log）。
