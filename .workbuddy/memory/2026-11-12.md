## Desktop 顶部一体化改造（Minimal Integrated Title Bar）

- **问题**：Windows/Linux 是「系统标题栏 + 默认 Electron 菜单栏 + 52px React 顶栏」
  三层叠加（主进程从未 setApplicationMenu，也没有 titleBarOverlay）；
  macOS 已是 hiddenInset 但顶栏 52px。
- **方案**：
  - Windows：`titleBarStyle: 'hidden'` + `titleBarOverlay`（color #f7f8f6 /
    symbol #30372f / height 44）——原生最小化/最大化/关闭画进顶栏右上角，
    Renderer 用 `env(titlebar-area-*)` 预留按钮安全区（实测 137px）；
  - macOS：保持 `hiddenInset`，顶栏左留 80px（原 92px 按 80 校正）；
  - Linux：保留系统标题栏（WCO 各桌面环境行为不一），仅 `autoHideMenuBar`。
  - 菜单：新增 `src/main/app-menu.ts`（role 组装，Ctrl+C/V/Z/A、Ctrl±缩放、
    F11 全屏等快捷键随 role 注册）+ `autoHideMenuBar` 收起传统栏 +
    IPC `app:popup-menu`（`Menu.getApplicationMenu().popup()`）——
    Renderer 顶栏轻量 ☰ 按钮弹同一份菜单，功能与快捷键一份不少。
  - 顶栏 52px → **44px**；`data-mac` 改为 `data-platform`（mac/windows/other）；
    画布工作区的 canvas-topbar（隐藏全局顶栏后它就是窗口顶栏）同步 44px +
    平台留白，修掉残留的 88px 红绿灯占位。
  - 新增 `shared/platform.ts` 统一平台判定；TopBar/CanvasPage 共用。
- **验证**：系统级截屏（CopyFromScreen，Playwright 拍不到 WCO 合成层）
  确认原生三键与顶栏同底色融合、最大化变还原键无错位；隔离实例实测
  topbar 44.0px / padding-right 137.4px / bar=drag / search+menu=no-drag；
  新增 `tests/e2e/app-shell.e2e.spec.ts` 3 条（44px+拖动分区、Windows 安全区+
  菜单入口、画布顶条同规格）。全量：unit **473/15**；e2e **41 passed / 6 skipped /

## Records masonry 右侧空白修复（2026-11-12 晚）

- 现象：记录页 4 张卡片只占左边两列，右侧约一半宽度空白。
- 排查：`.record-masonry` 容器全宽 1133px、computed column-count = 4
  （每列 270px），但 4 个 tile 只落在 col1/col2（x=28/316）——多列平衡器
  的分配问题，不是容器宽度问题。
- 根因：`.record-masonry .record-tile { display: inline-flex }`。inline 级
  盒子在 Chromium 多列平衡算法下被当行内内容按「行」分配，只填前几列。
- 修复：改为 `display: flex`（块级 flex，保持 tile 内部纵向布局）。
  实时样式突变实验验证：inline-flex → [2,2,0,0]；flex → [1,1,1,1]。
- 回归：smoke e2e passed；settings e2e 仍为既有路径分隔符失败（无关）。
