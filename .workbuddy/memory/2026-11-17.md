**1.1.2.1**（本轮，仅文档）关闭第三轮审查的 C-1 + 修正 O-1：

* C-1：README 那句「客户端的伪造条目只会被推到更左侧，永远不落在选中位置」是**错的**。
  `index = len - hops`，HOPS **过大**时选中位置左移到客户端可控条目 → **fail-open**。
  实测：单层追加式配 `HOPS=2`（XFF `1.2.3.4, 203.0.113.10`）选中 `1.2.3.4`；两层配
  `HOPS=3` 选中 `5.5.5.5`。现改为「过小 fail-closed / 过大 fail-open」双向说明 +
  「按真实链路核对，不要多加几层更安全」。另两处同源绝对化表述一并加限定
  （通用段落「在 HOPS 与真实链路匹配的前提下」、Nginx 追加式小标题）。
* O-1：Map 实际上界 = `maxBuckets` + 端点 overflow 桶数（overflow 桶自身也占条目），
  生产三端点理论上界 **10003**，不是严格 10000。报告新增 §4 子节，README 安全边界段同步。
