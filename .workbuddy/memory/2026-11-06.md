## v1.2 前置审查：缓存 Key 与焦点重锚（2026-11-06 午）

- **ImageStore.cacheKey(_:thumbnail:)** 是唯一的缓存键构造点（save/image/
  delete 共用）。教训：NSCache 键拼接散落多处迟早分叉——save 曾写裸文件名、
  读取走 name|false，保存的缓存永远命不中。缓存契约测试用「删盘文件验证
  缓存命中」的行为法，不查字符串常量。
- **BeanDeck.resolvedFocus(focusedID:index:ids:)**：焦点解析的纯函数。
  契约：豆在架 → deck 跟随重排（按 id）；豆离架 → index 钳位 + 焦点重锚到
  屏幕上的替补卡。**旧 bug**：focusedID 在豆离架后不清，旧豆恢复时 deck
  无手势跳回。视图 onChange(of: items) 只调这个函数。
- 判定为「产品行为选择、非 bug」的：全部喝完后 BeanStack 整体卸载重置状态；
  冲煮后重排跟随焦点豆（既有契约）；被删除的豆不可恢复。
- 526 条测试。Coffee Shelf 改版前的基础已就绪：图片读取有缓存契约钉着，
  焦点状态有纯函数与测试，改版动视觉层时这两块不用再碰。

### 补遗：onAppear 越界钳位（同日）

BeanStack 首次出现也走 `resolvedFocus`：调试启动 `--card-index` 越界时原来
会算出空窗口（页面没有卡片），现在钳回范围内并锚定焦点。约定：**deck 的
index/focusedID 只允许经 resolvedFocus 改写**，onAppear 与 onChange(of: items)
是仅有的两个入口。新增 testFirstAppearanceClampsAnOutOfRangeIndex；527 条测试。

## Records Masonry 前置：MasonryColumnPlanner（2026-11-06 午后）

为 Records 两列瀑布流改版打的算法地基，**只做算法与测试，未接 UI**：

- **`Core/MasonryColumnPlanner.swift`**（纯 Foundation，值类型 + Sendable，
  无 @unchecked）：`MasonryLayoutItem`（id + 高度，入口处防御——NaN/±∞/负 → 0、
  上限 10_000 防两条相加溢出成 inf）、`MasonryColumn`（left/right）、
  `MasonryColumnPlanner`（struct 本身即快照，拷贝就是快照，不需要单独类型）。
- **最短列优先贪心**：比高度 → 平局比条数 → 再平局进左列（首条必进左）。
  字典只做 id→列查询，顺序真相在数组里——确定性由此保证。
- **API**：`rebuild(with:)`（首载与筛选/宽度重建共用）、`append(_:)`（分页追加，
  O(1)/条，重复 id 静默跳过）、`updateHeight(of:to:)`（只改高度与累计，**永不
  换列**——防图片加载后闪动）、`remove(id:)`（安全删除，其余归属不动）；
  读取口 `items(in:)/totalHeight(of:)/column(of:)/height(of:)/recordCount/isEmpty`。
- **累计高度契约**：sum + 间距×(条数−1)；`rebuild` 精确重建，增量路径 O(1)
  变化量，末位浮点差异由测试按 0.001 精度钉住；最后一根拔掉直接置 0 不留漂移。
- **给下阶段的约定**：UI 接入时列高度必须从 planner 读，不许视图自算；
  测高修正走 `updateHeight`，禁止用「整体 rebuild」响应图片加载。
- 30 条契约测试（手算贪心轨迹贯穿）；全量 557 条通过。教训：4 处失败全是
  测试自己的手算漏了落列增量——行为断言必须连总量一起算对。

## Records Phase 3.1（ab37ca0）——稳定性收尾

### 更正上一节的测试口径（重要）
- **Phase 3 的「Executed 600, 0 failures」不可信**：`DemoData.install` 从
  Phase 2（b6f7b47）起就因 `tagAssignments[index]` 越界而崩（19 条示例记录

  崩溃前那次运行的 totals 被当成最终结果。本次已修（超出部分不贴标签）。
- 判断测试是否真的全绿：`grep "Fatal error"` 必须为空，且最后一行是
  `** TEST SUCCEEDED **`；只看 "Executed N tests" 会被重启后的分段统计骗。
- 当前真实基线：**625 条、0 失败**（新增 17 条）。

### 动画串行
- `InsertionSequence`（Features/Records）是纯状态机：`enqueue/takeNext/
  finishActive/cancel`，一次只允许一条处于下落位；视图用
  `withAnimation(_:completion:)`（iOS 17+，本项目 18）推进，**不再用
  520ms 间隔 + 760ms 清理**两个互不知情的定时器。
- 2s 失败超时只是兜底（完成回调不来时防队列卡死），不是动画节奏；
  `finishDrop(of:)` 用 activeID 做幂等。
- 每条记录插入前过 `RecordsDataSource.canInsert(_:for:)`：查询已切换、
  仍匹配、未在列表，三者缺一不可；查询变化/离开页面取消序列，记录已在库里。

### Reduce Motion
- `InsertionMotion`（offset / isOpacityOnly）把「无位移」变成可断言事实；
  Reduce Motion 用 `.opacity` transition + `Motion.fade`（0.2s）。

### 去重
- 两处 `known` 必须是 `var` 且追加后立即 insert：`fetchSearchResults`
  （多标签命中同一条）与 `append`（批内重复 id）。测试先红后绿。

### 分页
- 单哨兵挂在**更高一列**的末尾（底边=内容底边），`footerColumn` 按
  `pageGeneration` 冻结（测量回传会让两列高度反复反超，哨兵跟着换列

- 渲染：`CanvasWorldLayer` 按世界尺寸布局，整层一次 `scaleEffect + offset`；
  节点不再各自 position/scale。平移缩放不再逐节点重排。
- 手势：平移/节点拖动都在命名屏幕坐标空间取位移（`canvas-screen`），
  节点位移 ÷ viewport.scale 得世界位移；拖动只改内存，松手一次 save。
  平移松手用 `predictedEndTranslation × 0.28` 做 0.42s 惯性。
- 点击语义：单击节点直接推 `RecordDetailView`；播放/暂停是独立 Button；
  备注/移除走 contextMenu（备注写 CanvasNode，不碰 Record.note）。
- 落位：20pt 步长 + 40pt 网格索引（`CanvasPlacement.OccupancyIndex`），
  100/300/500 占位有耗时回归测试（<0.2s）。
- 缩略图：`CanvasThumbnailPreview` + `CanvasThumbnailData`（包围盒用全部节点，
  最多画 8 个、四类各一、确定性），只读本地缩略图；空画布回退名字色块。

## Canvas 1.1.1 / 1.1.2（87a031b）——节点消失的真根因与数据安全收口

### 根因（有运行时证据，不是推测）
1. **`try? fetch ?? []` 删光节点**：日志实测
   `canvas: record fetch failed — 未能打开该文件，因为它的格式不正确。`
   按一批 UUID 取 `Record` 会抛错；旧代码把异常当空数组 → 所有节点判成孤儿
   → delete + save。这就是「退出画布再进来节点全没了」。
2. **装窗用了占位尺寸**：`onGeometryChange` 在本页报过 800×800 / 2460×2976，
   真实画布区是 402×740。按占位尺寸算的视口把内容推出屏幕；旧实现一次性
   `didFit` 开关，真实尺寸到达后不再重算 → 节点在库里但看不见。
   **装窗尺寸一律用 `GeometryReader { geo in }` 的 `geo.size`。**

### 数据契约（已落进 MEMORY.md）
- `CanvasNodeReconciler.reconcile` 是唯一的对账/清理入口：读取失败 →
  `didFail`、一个不删；成功 → 只删确认缺失的 + touch 画布；保存失败 rollback。
- `CanvasNodeStore.nodes(in:)` 改为 **throws**；`add` 去重基于成功读取；
  `remove` 返回 Bool（界面只在这时才撤下卡片）。
- 工作区去掉 `@Query`：进入时显式读一次 → 对账 → 渲染。
- 删除记录/画布/示例数据都要 touch 受影响画布（缩略图刷新）。

### 交互与性能
- 新增 `CanvasPinchBridge`（UIPinchGestureRecognizer 挂祖先视图，
  `cancelsTouchesInView=false`、不改命中测试）→ 两指中心可跟随；
  `CanvasViewport.pinched(to:centroid:anchorWorld:)` 一起解缩放与平移。
- 节点不再接收 `scale`/`isPinching`：`CanvasCamera` 引用盒子 + 拖动开始时读一次
  缩放、偏移按世界单位；`CanvasNodeLayer` 实现 Equatable，平移缩放不再重算 body。
- 缩略图选点改为「载体各一 + 离已选最远补齐」（确定性），铺得开的画布不再只画左上角。

### 验收
- 新增 `CanvasPersistenceTests`（6 条，真实临时磁盘库，含跨容器重开、读取失败
  不删节点、混合缺失 ID）。全量 **690 条、0 失败**；本地化 1092 键不变。
- 模拟器实测（iPhone 16 Pro / 18.6）：4 节点（含负坐标）全部可见 36%；
  `simctl terminate` 重启后库里 4 行、坐标层级一致、`purged 0`、截图逐像素相同。
- 未做：真机手势（捏合中心/拖动跟手）、点击级返回列表再进入（simctl 不能点击）。

  sheet 尺寸不是真实窗口尺寸）+ `-BrewPhaseCanvasSeed yes`（幂等落 4 个节点）。
