## v1.2 前置审查：缓存 Key 与焦点重锚（2026-11-06 午）

- **ImageStore.cacheKey(_:thumbnail:)** 是唯一的缓存键构造点（save/image/
  delete 共用）。教训：NSCache 键拼接散落多处迟早分叉——save 曾写裸文件名、
  读取走 name|false，保存的缓存永远命不中。缓存契约测试用「删盘文件验证
  缓存命中」的行为法，不查字符串常量。
- **BeanDeck.resolvedFocus(focusedID:index:ids:)**：焦点解析的纯函数。
  契约：豆在架 → deck 跟随重排（按 id）；豆离架 → index 钳位 + 焦点重锚到
  屏幕上的替补卡。**旧 bug**：focusedID 在豆离架后不清，旧豆恢复时 deck
  无手势跳回。视图 onChange(of: items) 只调这个函数。
- 判定为「产品行为选择、非 bug」的：全部喝完后 BeanStack 整体卸载重置状态；
  冲煮后重排跟随焦点豆（既有契约）；被删除的豆不可恢复。
- 526 条测试。Coffee Shelf 改版前的基础已就绪：图片读取有缓存契约钉着，
  焦点状态有纯函数与测试，改版动视觉层时这两块不用再碰。

### 补遗：onAppear 越界钳位（同日）

BeanStack 首次出现也走 `resolvedFocus`：调试启动 `--card-index` 越界时原来
会算出空窗口（页面没有卡片），现在钳回范围内并锚定焦点。约定：**deck 的
index/focusedID 只允许经 resolvedFocus 改写**，onAppear 与 onChange(of: items)
是仅有的两个入口。新增 testFirstAppearanceClampsAnOutOfRangeIndex；527 条测试。

## Records Masonry 前置：MasonryColumnPlanner（2026-11-06 午后）

为 Records 两列瀑布流改版打的算法地基，**只做算法与测试，未接 UI**：

- **`Core/MasonryColumnPlanner.swift`**（纯 Foundation，值类型 + Sendable，
  无 @unchecked）：`MasonryLayoutItem`（id + 高度，入口处防御——NaN/±∞/负 → 0、
  上限 10_000 防两条相加溢出成 inf）、`MasonryColumn`（left/right）、
  `MasonryColumnPlanner`（struct 本身即快照，拷贝就是快照，不需要单独类型）。
- **最短列优先贪心**：比高度 → 平局比条数 → 再平局进左列（首条必进左）。
  字典只做 id→列查询，顺序真相在数组里——确定性由此保证。
- **API**：`rebuild(with:)`（首载与筛选/宽度重建共用）、`append(_:)`（分页追加，
  O(1)/条，重复 id 静默跳过）、`updateHeight(of:to:)`（只改高度与累计，**永不
  换列**——防图片加载后闪动）、`remove(id:)`（安全删除，其余归属不动）；
  读取口 `items(in:)/totalHeight(of:)/column(of:)/height(of:)/recordCount/isEmpty`。
- **累计高度契约**：sum + 间距×(条数−1)；`rebuild` 精确重建，增量路径 O(1)
  变化量，末位浮点差异由测试按 0.001 精度钉住；最后一根拔掉直接置 0 不留漂移。
- **给下阶段的约定**：UI 接入时列高度必须从 planner 读，不许视图自算；
  测高修正走 `updateHeight`，禁止用「整体 rebuild」响应图片加载。
- 30 条契约测试（手算贪心轨迹贯穿）；全量 557 条通过。教训：4 处失败全是
  测试自己的手算漏了落列增量——行为断言必须连总量一起算对。

## Records Masonry Phase 2：UI 接入与真分页（2026-11-06 午后 II）

- **`insertNewest`**（Planner）：选列规则与 append 一致，落点是列首；
  空列不加间距；重复 id 忽略。7 条新契约测试。
- **`ImageStore.imageDimensions`**：ImageIO 读文件头（不解码整图）+
  EXIF 5–8 方向交换校正 + NSCache 内存缓存；save 顺手预热；delete/
  clearCache 同步清。`ImageDimensions` 值类型给 Masonry 预留比例高度。
- **`RecordCardHeightEstimator`**：按载体与列宽估算（图片真实比例、文本
  0.72 字宽折行、行数上限与窄卡排版对齐）。窄卡约定：**标题只在用户
  真填过时显示**——displayTitle 会回退到备注首行，不区分会重复。
- **`RecordsDataSource`**：三模式取数——浏览=数据库偏移分页（20/批，
  删除错位靠 id 去重兜住）；搜索=字段谓词全量 + 标签名命中并集（搜索必须
  覆盖全数据集）；标签=关系内排序分批。`matches` 是谓词的内存镜像，
  两边必须同步改。`insertNewAtTop` 在浏览模式把游标 +1（对齐偏移）。
  `staleIDs()` 协调删除/编辑出筛选范围的记录。
- **`RecordsMasonryView`**：共享 ScrollView + HStack 两列 LazyVStack；
  列归属只来自 Planner；实测高度 onGeometryChange 回传（阈值 0.75pt，
  updateHeight 不换列 → 无测量循环）。宽度变化 = 允许的重建场景。
- **`RecordsView`**：常驻搜索 + 单行标签栏 + Masonry 内容区；搜索防抖
  250ms；AddFlowView/RecordEditorView 的 onSaved 改为带 Record（顶部
  插入用）；详情返回 onAppear 协调；删除保持「先落库后删文件」。
- **DemoData**：示例图片改为安装时本机生成（渐变，isSample 标记，
  removeInstalled 落库后连媒体文件一起删）；记录扩到 ~27 条（两页）供
  翻页验收。
