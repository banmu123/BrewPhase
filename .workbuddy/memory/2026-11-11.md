## Studio Home Phase 1.3：舞台高度改为内容驱动（修三栏空洞）

- **症状**：三栏并排后咖啡那栏上方空 169px（豆袋底部对齐、舞台固定 286），记录下方空 160px（叠放卡顶部对齐）。原因是舞台固定 286px，而内容高度只有 117 / 122 / 234。
- **根因**：三个堆叠容器（`.coffee-shelf` / `.records-deck` / `.canvas-deck`）都是 `position:absolute; inset:0`，不贡献高度，只能靠舞台 `min-height` 托住 —— 于是「固定高度」和「内容高度」必然不一致。
- **修法**：
  - 舞台 `min-height: 0`，只在 `:has(.studio-empty)` 时给 268 的空态底线（空态装饰是 absolute，需要这个下限）。
  - `.studio-space`（subgrid）加 `align-items: start`，舞台不再被拉到整行高。
  - 咖啡架：`position: relative` + `aspect-ratio: 系数/1.485`，卡宽由组件按张数算 `--cw: calc(100% / 系数)`（系数 1 / 1.70 / 2.46 / 3.15 / 3.89，对应 CSS 里那几档负边距），于是**不管几包都铺满一列**、高度自然等于豆袋高度。
  - 记录 / 画布：容器改 `position: relative`，**第一张卡留在文档流**（`:first-child { position: relative }`），由它撑高容器，其余卡继续 absolute 叠放。
  - 画布缩略图新增 `height="fluid"`，首页用 16:10 随列宽缩放（Gallery 仍是固定 168）。
  - 记录卡宽 70%→62%，让这一叠的可见下缘与另外两栏接近。
- 实测（1440/1280/1100/980）：标题→内容间距 13–17px，三栏可见底边极差 16 / 16 / 20 / 24px，`overflowX = 0`。
- **测试坑（重要）**：Playwright 没发过 `mouse.move` 之前，页面的 `:hover` 来自**真实系统光标**的位置。测试机光标恰好落在记录这栏，页面一加载卡片就是展开姿态，`restFirst` 读到的是展开值，`hover 后位移差 > 10px` 得到 0.33px 的假失败。修法：读紧凑姿态前先 `mouse.move(4,4)` 并 `expect.poll(deckHovered).toBe(false)`。
- 新增回归用例「有数据时三栏都不留空洞，底边也接近」：断言 headGap ≤ 30、舞台高度 ≤ 可见底 + 8、三栏底边极差 ≤ 40。

## Studio Home Phase 1.4：Records 一叠在列内居中

- **症状**：记录卡贴列左边缘（1440 下左空 0 / 右空 78px），整摞被挤到一侧。
- **第一次改错**：只居中第一张（`left: calc((100% - 卡宽)/2)`），结果整摞仍偏右 —— `DECK_REST` 向右下扇开 68px，可见跨度是「卡宽 + 扇开量」，左空 73px、右空只剩 5px。居中要按**整叠可见宽度**算。
- **正解**：`--card-w` 与 `--deck-fan` 两个变量，`left: calc((100% - var(--card-w) - var(--deck-fan)) / 2)`；`--deck-fan` 由组件按实际张数注入（`DECK_REST.slice(0, n)` 的最大 x，1 张 = 0、5 张 = 68），只有 1–2 条记录时也不会偏。
- 第一张卡在文档流里（撑高容器），不能用 `left`（相对定位会二次偏移），改用同一条公式的 `margin-left`。
- 实测四档：左右各 39 / 39 / 30 / 23px，偏心 0。新增回归用例「Records 一叠在列内水平居中」（偏心 ≤ 6px、左留白 ≥ 8px）。
- **测试坑（再次）**：真实系统光标停在某张卡上时，那张卡拿到 `:hover { z-index: 30 }`，会盖住第一张，命中测试假红；窗口 resize 后布局位移、光标可能又落回这一叠。所以每档宽度都要重新 `mouse.move(2,2)` + 等 `:hover` 解除，并先关掉 transition。
