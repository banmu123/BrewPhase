## Desktop：Phase 3.2 同步后自动补全 + 搜索/详情接入派生元数据

- **ResolveQueue**（`metadata/resolve-queue.ts`）：并发 2、幂等键 `recordId+urlString`、
  失败不重试、`onSettled` 广播 `records:metadata-updated`。执行体**同步启动**
  （`enqueue` 后立刻进入 running），否则测试里 release 打不到 gate。
- **触发点**：`SyncServer` 在 `applyBatch()` 返回（事务已提交）后回调 `onApplied`，

  `prepareLocalMetadata()` → 需要时入队。**网络永不在事务里**。
  `skipped/conflict/failed` 一律不入队。

  记录仍是 link 的行；不恢复 failed。
- **搜索**：`listRecords` 用 EXISTS 子查询接入 record_metadata（url 必须一致），
  不用 JOIN（关系不唯一会出现重复行、分页错位）。

## 撤销配对清空 + 记录增删自动推送（两端）

**真机现象**：iOS 删除记录后桌面没变。查库发现桌面最后一次收到请求是 16:42:14
（`last_seen_at` / `change_log` 都停在那），删除请求根本没发出去；`devices` 表里
11/7 一天配对 8 次、每次几分钟就撤销——撤销只能来自桌面「撤销授权」按钮。

**清空（两端都能触发，只清同步实体）**：
- 桌面 `src/main/sync/wipe.ts`：清 records / record_tags / record_tag_links /
  record_metadata / canvases / canvas_nodes / canvas_strokes + 这些记录引用的媒体
  （含 `_thumb`）+ sync_baseline·sync_conflicts·sync_rejected·change_log 里的同步实体行。
  **豆子/冲煮/品鉴/阶段规则保留**——这是产品边界。
- `POST /api/sync/wipe`：已配对 token + HMAC + body 必须带
  `{"confirm":"DELETE_SYNCED_CONTENT"}`，否则 400；清完广播 `sync:changed`。
- Mac 设置页：撤销授权 → 分「只撤销授权」「撤销并清空内容」两个按钮，不塞进一个确认框。
- iOS：`SyncNetworkClient.wipeSyncedContent()`；`SyncManager.unpair(wipeRemote:)`
  **先清远端再清 Keychain**（反了就发不出请求）；远端失败仍清本地，并区分
  「已断开」与「没清成」两种结果文案。

**顺手修的真缺陷**：`pair()` 成功后没清基线 → 重新配对后首次同步只发增量，
桌面缺的数据永远补不回来（也解释了 16:42 那次只 applied 1 条）。现在配对成功即
`baseline = [:]` + 重置 lastSyncAt。

**自动推送**：记录保存 / 删除后 `SyncManager.shared.scheduleAutoSync(context:)`，
2 秒合并窗口，未配对直接返回，`isRunning` 与手动同步互斥（第二轮直接放弃，
快照是当前状态，排队跑过期快照没意义）。
- `SyncSnapshotBuilder.fileSHA256` 加 `(路径, 大小, mtime)` 缓存：否则每编辑一条
  记录都要把所有视频从头读一遍，自动推送会变成卡顿源。

**验证**：桌面 vitest 270/270（+3 wipe 单测、+2 路由测试）、typecheck、build、
E2E 6 passed / 1 skipped（新增 sync-unpair-wipe）；iOS `xcodebuild test`
**701 tests / 0 failures**。
- **红检踩到的坑**：E2E 里「切页后 `.record-tile` 数量为 0」是假阳性——组件刚
  挂载、items 还是空数组就满足了断言。删除类测试必须直接查库。
  红检确认：去掉 `delete from records` 后，改过的断言能红（Expected 0 / Received 1）。
