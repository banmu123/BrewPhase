# 2026-11-08

## Desktop：Link Resolver 第四轮（IPv6 特殊用途 / Inspector 编辑态 / 状态语义 / Gist）

- **IPv6 判定改成「解析 + 按位前缀」**：`parseIPv6` 支持 `::` 压缩、内嵌 IPv4、
  zone id；策略是**只放行全球单播 2000::/3**，再在段内排除 IANA 特殊用途
  （2001::/23、2001:db8::/32、2002::/16 6to4、3fff::/20 文档）。
  `64:ff9b::/96`（NAT64 WKP）、`64:ff9b:1::/48`（RFC 8215 本地 NAT64）、
  `100::/64`、`5f00::/16`、ULA/link-local/组播全部落在 2000::/3 之外 → 明确拒绝。
  **不要再写字符串前缀判断**：`startsWith('2001')` 会误伤 `2001:4860::`（Google）。
- **RecordInspector 编辑态**：新增纯函数 `inspector-state.ts`（title/note/URL/标签
  四个 dirty 标记）。异步元数据补全后列表重载，只同步「用户没改过」的字段；
  改过的保留用户输入；记录切换才整体重置。**不要再 `useEffect(..., [item.id])`
  一次性覆盖全部字段**——那正是自动标题被空输入框覆盖的原因。
- **metadataStatus 语义**：刷新失败保留原状态（ok/resolved/partial 各自不变，
  不把 partial 悄悄升成 ok）；从未成功过才落 failed；本次成功一律 ok。
- **元数据写入**：UPDATE 的 WHERE 同时带 `urlString` 与 `carrier='link'`。
- **Gist**：`gist.github.com` 的 `repositoryOwner/Name` 是 null，旧代码恒定失败；
  现在走公开 `/gists/{id}` API（描述→标题、文件名→描述、owner→作者），
  无封面则回退仓库信息卡，不复用仓库统计字段。
- **真实网络 smoke**：`METADATA_LIVE_SMOKE=1 pnpm test:live`
  （`vitest.live.config.ts` + `tests/live/*.smoke.ts`）。普通 `pnpm test` 完全不碰它。
  首跑就抓到两个真问题：X 的 `status/20`（第一条推文，短 ID）被 `\d{5,25}` 挡掉
  → 放宽成 `\d{1,20}(?=/|$)`；本沙箱 `HTTP_PROXY` 把 `api.github.com` 解析成
  127.0.0.1，被 SSRF 防护正确拦截（**不是 bug**，真机需本地复跑确认）。
- 验证：vitest 189/189、typecheck 双工程、build、E2E 3/3。
