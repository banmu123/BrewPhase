## 圆桌/浮窗标题栏与 WCO 色差修复（09:4x）

用户截图反馈：独立圆桌窗口右上角系统按钮（— □ ✕）区域与导航栏有色差。

- **像素级定位**（Python 手解 PNG 采样）：标题栏左侧 DOM = `#FFFFFF`
  （`.rt-window__titlebar` 用了 `--card`），右侧 x≥1664（2x DPI，CSS 832px
  起 = 136px WCO 安全区）= `#F7F8F6`。后者正是主进程 `WINDOW_CHROME.light
  .background` = `--paper`——Windows titleBarOverlay 原生按钮区域永远画在
  DOM 之上，DOM 用别的表面色就留出一块色差。主窗口没事是因为 `.topbar`
  本来就用 `--paper`。
- **修复**：
  - `.rt-window__titlebar` 背景 `--card` → `--paper`；
  - `.bp-float__titlebar` 背景 `--paper-deep` → `--paper`（同族隐患一起修）；
  - 两处加注释：WCO 区域底色来源是主进程 WINDOW_CHROME（= --paper），
    DOM 标题栏必须同源，否则右上角出色差。
  - `roundtable-window-manager.ts` / `float-window.ts` 的初始 chrome 从
    硬编码 `WINDOW_CHROME.light` 改为 `WINDOW_CHROME[initialWindowAppearance()]`
    （与主窗口一致，深色系统拆出/拖出不闪浅色首帧）。
- 验证：`pnpm typecheck` ✅、`pnpm build` ✅；tests 无 titlebar 颜色断言。
- 顺带发现（未改）：`.spacer` 只有 `.canvas-topbar .spacer` 有 flex:1 定义，
  `.rt-window__titlebar` / `.bp-float__titlebar` 里的 `<span className="spacer" />`
  无效，按钮组挤在左侧而不是靠右。用户未反馈，留观察。

## 卡片架会话恢复（重启不再丢卡，10:5x）

用户反馈：「正在使用」里保存的网页卡重启客户端后消失。根因：标签
（tabs）完全是内存态（BrowserTabManager 无任何持久化），重启即清空。

- **方案：标签会话快照**（不新增 migration）——沿用 local_state KV：
  键 `browser.tabSession`，`{ seq, tabs:[{id,url,title}] }`，zod 校验
  （`browserTabSessionSchema`，上限 24 张，id 必须 `tab-\d{1,6}`）。
- **tabId 原样恢复是核心设计**：圆桌面板布局（roundtable_panels）、成员
  participantTabIds、cardOrder 全按 tabId 持久化引用；编号一样，重启后
  这些记录不用迁移就能重新命中（4.2b 幽灵面板问题随之消失）。seq 取
  max 推进，新 tab 永不与旧记录撞车。
- 恢复的卡全部 park 进采集宿主（安静加载，点击展开）；activeTab 不恢复
  （起始页开始）。空白卡（无 url）不持久化。close() 关掉全部卡后重启
  → 空架，一致。
- 写时机：TabManager onChange 防抖 600ms + dispose() 同步 flush
  （before-quit / 数据迁移都走 dispose）。读时机：BrowserManager 构造
  末尾 restoreSession()。
- **坑**：第一次实现定义了 restoreSession 却忘了在构造函数里调用——
  单测抓到（tabs 恢复为空），修复后过。
- 测试：tab-manager 3 条（id/协议/重复拒绝、seq 推进、真实加载）+
  manager 3 条（恢复+park、编号推进、关空后重启空架）；全量 808/808 ✅。
  E2E：browser/web-cards/detach/bookmarks 20 passed，仅 browser.e2e
  「拖动与缩放」已知无 GPU 环境失败（与本次无关）。
- 手工验收：开几张卡 → 完全退出 → 重启 → 卡片架原样回来、圆桌成员/
  面板不再幽灵化。

- **本地打包三连坑**（都在 `pnpm exec electron-builder` 阶段）：
  1. `unable to verify the first certificate`：本地代理
     127.0.0.1:61285（MITM）拦截 electron zip 下载 → `env -u http_proxy …`
