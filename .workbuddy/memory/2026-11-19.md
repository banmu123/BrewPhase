## Phase 1.3.1-C3a-R1：Token 请求体与媒体类型硬化

- 三处请求面问题：`body.length`（UTF-16 码元）当字节、先 `c.req.text()` 再判大小、
  `contentType.startsWith(...)`。全部修在 `cloud/src/routes/mcp-oauth.ts` 的
  `readBoundedBody` / `isFormContentType` / `decodeFormBody`。
- **读法固定**：Content-Length 校验（`/^\d+$/`，**不要用 `Number.isInteger`**——
  `Number("")` 是 0，空头会被当零字节放行）→ 流式累加 `byteLength`（超 8192
  `reader.cancel()`）→ 合并 → `TextDecoder("utf-8", { fatal: true })` → URLSearchParams。
- **顺序不能反**：先截断再解码，否则「超限」与「非法 UTF-8」互相掩盖。
- `app.request()` 会**规范化 header**：`content-type` 的尾随空格会被 undici 去掉，
  所以「尾随空格」这种用例测不到我们的解析层，别写。
- 写这类测试的教训：**必须用「完整合法表单 + 只破坏一个维度」**。半截表单会让
  400 来自「缺 client_id」而不是被测的判据，变异就存活了（M4/M5/M7 第一版全栽在这）。
- 变异 7/7；门禁 Cloud 993 → **1009**（61 files，+16），Desktop 1265 / 89 不变。
- 1 MiB 流式计数用例是「边读边截断」唯一的可观测判据：只断言 400 区分不出

## Phase 1.3.1-C3c-1-R1：BASE_URL Origin 校验加固

- 根因：`assertIssuerBaseUrl()` 读的是**解析之后**的视图（`url.pathname`），
  而 WHATWG 会先做路径规范化——`/api/..`、`/..`、`/a/%2E%2E`、`/a\..` 的
  `pathname` 全是 `/`。`loadEnv()` 保留原始串，于是 `iss` 变成带路径的值，
  三处仍然一致、但没有一处是 origin。
- 同族漏判：`https:///api` 解析出的 host 是 `api`（原始串无 authority）；
  `https://@host` 的 `username`/`password` 都是空串（`@` 只在原始串里）。
- 修法：先在原始串切 `scheme://` + authority（不用 `split(":")`，IPv6 有冒号），
  再交给 `URL` 做合法性与字段校验；不归一化、不替换成 `origin`。
- **Zod 4 的 `.url()` 会先 trim**，所以「BASE_URL 不许有空白」的分支不可达，
  已删——写校验前先确认上游 schema 是否已经动过值。
- 测试 11 → 16（Cloud 1110 → **1115 / 63 files**），含 IPv6 与 dev localhost
  两条正向用例；变异 4/4（退回 pathname 判断转红 5 条）。

## Phase 1.3.1-C3c-2：严格 CIMD Fetcher

- 依据 `draft-…-client-id-metadata-document-03`（Internet-Draft）。只交付抓取器，
  **不接入 authorize**，元数据不声明 `client_id_metadata_document_supported`。
- URL 判断在**原始字符串**上做（同 C3c-1-R1 的教训）：`/a/..`、`/%2e%2e` 解析后
  `pathname` 都是 `/`。端口只 443、拒绝 query 是**项目自己的**更严格策略。
- **BlockList 的坑**：它内部把 IPv4 存成 `::ffff:a.b.c.d`，把 `::ffff:0:0/96`
  加进同一张表会让 `8.8.8.8` 也被判私有。映射地址要用第二张 BlockList 识别。
- DNS Pinning：解析一次拿全部 A/AAAA → 全部必须公网 → 连接只用第一个地址；
  `lookup` 必须同时支持 `{all:true}` 与三参形态，否则会**回落真实 DNS**。
  代理模式 CONNECT 到 IP、TLS SNI 用原域名；`socks5://` 必须抛错（不能像
  Provider 通道那样回退直连）。
- 5 KiB 是**流式**上限：Content-Length 预检 + 实际字节累计，超限立即 destroy。
- `no-store` 不可缓存、`no-cache` 立刻过期、`s-maxage` 优先于 `max-age`；
  transient/terminal 不共用处理逻辑（网络抖动不能作废缓存）。
- WebFetch 拿到的草案原文说明：`client_name`/`redirect_uris` 在草案里**不是**
  MUST，本项目按产品需要列为必需——文档里要标明这是项目策略。

## Phase 1.3.1-C3c-2-R1：CIMD Fetcher 安全加固

- **HTTPS 代理**：`openTunnel` 原来一律 `http.request` 连代理，`https://` 代理被明文
  访问（凭据同行走明文）。现在按协议分支：`https:` 先 `tls.connect`（默认校验证书）
  再在隧道上发 CONNECT；`TunnelOptions` 只有 `ca`，没有关闭校验的入口。
  在已连 socket 上发 CONNECT 的写法：`http.request({method:'CONNECT', path, headers,
  createConnection:()=>socket})`，**不能带 `agent`**（agent:false 会忽略 createConnection）。
- **DNS 预算**：`await` 之后再检查耗时 = 没检查。`withDeadline()` 把工作分支先
  `.then(v=>…, e=>…)` 成永不 reject 的 promise 再与只 resolve 的定时器竞速，
  迟到结果被吸收，不会有 unhandledRejection。默认时钟换 `performance.now()`。
- **IPv6 白名单**：黑名单挡不住未分配段（`4000::1`/`c000::1`）。先要求 `2000::/3`。
  注意 `3fff::/20` 是文档段，边界用例要取 `3fff:ffff::1`。
- **状态分类**：408/425/429/5xx → transient；3xx/其它 4xx → terminal；只有 200 解析。
  原来的「非 200 → terminal」样本 503 必须换成 404，否则与本轮目标冲突。
- **5 KiB 可证明性**：`Readable.from` 读完会自动 destroy，用 `destroyed` 断言
  「我们主动停读」是**假阳性**（第一版变异没抓住）。要用按需生产的源 + `_read`
  计数上界。
- 测试引入 `cloud/tests/fixtures/` 自签名证书（仅测试；客户端把它当 `ca` 时握手成功、
  不传时必须被拒）。测试 helper 关不掉时先查 CONNECT socket 与 pipe 出来的 upstream
  ——`closeAllConnections()` 不管 CONNECT socket。
- 变异 5/5；门禁 Cloud 1264 → **1333 / 65 files**，Desktop 1265 / 89 不变。
  首轮全量有一次 `authorize-route` 的 1ms TTL 抖动（600001 ≤ 600000），与改动无关，
  重跑即绿，未改断言。
