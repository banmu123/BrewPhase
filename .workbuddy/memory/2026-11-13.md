  已实测：后台 view 能 loadURL + executeJavaScript，两个可并行；
  **必须 `backgroundThrottling: false`**，否则后台页流式渲染被节流。
- **自动化全在主进程**：Adapter 只出「在页面里跑的脚本」+ 域名白名单；
  选择器集中多候选；写入用 `execCommand('insertText')`（contenteditable 上
  React/ProseMirror 最能感知）；完成判定 = 停止按钮消失 + 回答文本连续两轮

  渲染层拿不到 executeJavaScript/Cookie，IPC 只有问/停/看。
- **同 origin 不重复 loadURL**：SPA reload 会丢当前对话；跨 origin 才重新加载。

## 可拆卸浏览器窗口（Phase 0.5）

- **架构**：`browser-runtime` 三件套——`browser-tab-manager`（tabId 身份、
  view 生杀**唯一**归属者）、`float-window`（独立窗口，关闭=归还 tab 不销毁）、
  `browser-view-factory`（view 创建 + session 加固唯一来源）。窗口只负责显示，
  `closed` 不销毁 webContents。
- **拆分=改 view 父窗口**：`contentView.removeChildView + addChildView`，
  WebContents 实例/URL/Session 全不变（e2e 用 fixture 页的 `__born`/
  `__ticks` 证明从未刷新）。
- **拖动归属判定在主进程**：渲染层 pointerup 报屏幕坐标 → `resolveDrop` →
  windowAt 遍历窗口 bounds 判定（主窗口=接回、浮窗=移入、窗外=新浮窗）。
  **坑**：`BrowserWindow.getAllWindows()[0]` 当主窗口引用不可靠（浮窗加入后
  顺序漂移），主窗口必须显式记录引用。
- **坑 1**：先 moveToWindow 再 release 浮窗账本，release 的是移动后的 id →
  空浮窗关不掉。**先记 fromWindowId，移动，再清旧账**。
- **坑 2**：浮窗壳漏 preload → `window.brewphase` undefined → React 初始化
  effect 抛 TypeError → **整树卸载只剩底色**，且 console 全静默（错误早于
  监听器附加）。壳与主窗口同一套 preload/sandbox。
- **坑 3**：file:// 壳页不要用 query 传参（loadFile search / URL ?），
  **用 hash**（`#bpFloat=<id>`），App 读 location.hash。
- **坑 4**：`page.screenshot` 拍不到 WebContentsView（空白≠没显示）。
  可见性用 `document.visibilityState === 'visible'` 探针验证。
- **坑 5**：CDP 注入的鼠标派发不到视口外——**UI 拖出屏幕外的自动化不可靠**，
  归属判定用 resolveDrop IPC 直接验证，真实手拖列为人工验收。
- 主窗口关闭 → `onMainWindowClosed()`（tab 转未挂载，浮窗存活）；
  `before-quit` 才 dispose 全部。
- **自动化**：`executeOnTab(tabId, script)` 按 tabId 定位、跨窗口不变；
  e2e 已验证拆分/拖回前后 DOM 读取一致。
- typecheck ✅；vitest **655**（tab-manager 生命周期 7 条新增）；build ✅；
  e2e：detach 全链路 1 条 + canvas/records/app-shell/settings/ai-workspace 9 条全过。
