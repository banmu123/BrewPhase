## 真机「开始同步即闪退」根因（13:35 修复）

- **根因**：`SyncNetworkClient.post` 用 `JSONSerialization.data(withJSONObject:)`，
  而 `apply()` 传入 Swift struct `SyncBatch` → JSONSerialization 抛
  **无法捕获的 NSException**（Invalid type in JSON write）→ 点同步后第一次
  apply 即闪退。iOS 侧此前没有跑过真实 apply 路径（桌面 wire-format 测试
  是桌面自构造请求），所以全绿也拦不住。
- **修复**：所有请求体统一 `JSONEncoder().encode` → `post(bodyData:)`；
  删除 `post(body: Any)` 变体杜绝复发。回归测试
  `testSyncBatchEncodesWithTSCompatibleKeys` 锁定键名（entityType/upserts/
  fingerprint/payload/expectedFingerprint）。
- **教训**：JSONSerialization 只能接纯 Foundation 集合；Swift struct 一律
  JSONEncoder。新同步客户端的「真实 HTTP 路径」必须有集成级测试。

## 真机「时间戳全 null」根因（0cbfa6c）

- **AnyCodableValue.init 动态转换陷阱**：epochMillis 返回 Int64?，装箱后
  `as Int` **失败**（Swift runtime 不做跨整型 dynamic cast，实测证伪）→
  全部时间戳（createdAt/roastDate 等没有 `?? 0` 兜底的字段）静默变 null →
  record_tags.created_at NOT NULL 失败，真机 52/11 条全败。有 `?? 0` 兜底的
  （brew.date 等）幸存——这个不对称正是定位线索。
- 修复：init 补 `case let value as Int64`；insertRow 对 created_at/updated_at
  null/undefined 补 now（NOT NULL 兜底）。两端回归测试。
- **教训**：`Int64 as? Int` 是 nil 不是桥接；Optional 装箱进 Any 后跨类型
  cast 全部失效。AnyCodableValue 这类动态容器必须显式列出所有数值宽度。
- 真机进展：配对 ✓、媒体上传 ✓（5 张图）、失败明细 UI 已上（用户能直接
  看到每条 reason）。仍待用户用修复后构建重试同步。
