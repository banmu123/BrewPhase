## 崩溃修复：添加豆子弹窗点「清除烘焙日期」即崩

用户报告：添加豆子 sheet 里烘焙日期旁的 ✕ 清除按钮一点就崩。

**根因**：`DateRow`（FormComponents.swift）用了 `Binding($date)` 对可选日期自动解包。
点 ✕ 执行 `date = nil` 的**同一帧**，仍挂在视图树上的 DatePicker 还会读一次这个
解包 binding——`Binding(unwrapping:)` 语义在读到 nil 时直接 trap → 崩溃。
这是 SwiftUI 的经典陷阱：自动解包绑定绝不能配一条「同生命周期内会把它写成 nil」的路径。

**修复**：手写绑定（`get: { date ?? lastKnown }` 永不返回 nil；`set` 同时记录
`lastKnown` 并写回），`@State lastKnown` 记住最近非空日期；「未填写」的恢复路径
改为回填记住的日期（比原来无条件 `Date()` 更合理）。全项目 `Binding($` 清零
（TastingEditor 的 DateRowCard 本就是非可选绑定，安全）；下游对 nil 烘焙日期的
处理（rulePreview/validation/save）本就有 guard。

**验证**：TEST BUILD SUCCEEDED；341 测试 0 失败；添加豆子页截图确认日期行 +
✕ 渲染正常（崩溃路径是结构性消除——不再存在可 trap 的解包绑定）。
同一组件修复自动覆盖 开封日期/购买日期 行的相同隐患。

**教训**：可选用法上凡是允许用户「清空」的绑定，一律手写 get 兜底，
禁用 `Binding($optional)` 自动解包。
