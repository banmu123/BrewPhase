## MCP Inspector 2.16 接 Remote MCP 的三个硬约束

1. **回调与 UI 同源同端口**：`getRedirectUrl() = ${window.location.origin}/oauth/callback`。从 `127.0.0.1:6274` 打开就是 `6274`，不是旧版约定的 `6276`。预注册 client `mcp-inspector-cli` 原 `redirect_uris` 只有 `6276`，已 SQL 补 `http://127.0.0.1:6274/oauth/callback`（该行是手工插入的，不在迁移里，重建库会丢）。
2. **不支持 DCR**：AS metadata 故意无 `registration_endpoint`（只允许 pre_registered + CIMD），Inspector 默认要注册 → 报 `does not support dynamic client registration`。解法是 catalog 条目加 `"oauth": {"clientId": "mcp-inspector-cli"}`（或 UI 里填 Client ID，Secret 留空）。
3. **`~/.mcp-inspector/storage/oauth.json.lock` 是目录且删不掉**（safe-delete broker denied；`rmdir` EPERM，`mv` 可以）。它会让每次 CLI/UI 写 OAuth 状态等 15s 后失败（表现为 `Failed to write store: 503` / CLI `unreachable`）。解法：`MCP_STORAGE_DIR=/tmp/mcp-inspector-storage`。

- 负向全绿：无/坏 token 401（`resource_metadata` 指向 `…/oauth-protected-resource/mcp`）、缺 scope 403 `insufficient_scope`、GET/DELETE 405、300KB 413、错误 Host/Origin 403、不存在 id → HTTP 200 + `isError`。
- `POST /mcp/oauth/revoke` **只撤 refresh token**，access token 返回 `unsupported_token_type`；但 `MAX_TOKEN_FIELD_LENGTH=512` 会先拦下 4-scope 的 JWT（516 字符），错误码变成 `invalid_request`——同一语义两种错误码，待统一。
