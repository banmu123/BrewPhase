
## Roundtable Phase 1：网页卡片架 + AI 圆桌（2026-11-14 午，未提交）

- 交付：Studio Home 三栏下方新增两层——「正在使用」网页卡片架（本地模拟
  数据，不连 WebContents）与 AI 圆桌（拖入参与者、整块拖出浮动、归位）。
- 分层：`shared/roundtable.ts` 纯函数（规则/排序/clamp）→
  `features/studio/roundtable-store.ts`（zustand，join/leave/close 三种
  操作语义）→ `WebCardShelf.tsx` / `RoundtableSection.tsx` 组件。
- **移除 AI Workspace 一级入口**（顶栏按钮 + `module==='ai'` 路由），
  底层 ai-chat 服务、MultiAI/Accounts/Conversations 组件、migration 10
  全部保留，等后续阶段以圆桌形式重新接入。ai-workspace.e2e 改为断言
  「入口已移除、圆桌就位」。
- **两个真实 bug 被自己测试抓到**：
  1. `setPointerCapture` 必须在记录起点**之后**、且 try/catch 包裹——
     无 GPU 环境可能抛异常把 `press.current` 赋值一起带走。
  2. **投递竞态**：圆桌与卡片各自挂 document pointerup，卡片 onUp 先
     `setDraggingCard(null)` → React 重渲染把圆桌的 effect 卸掉 →
     圆桌的 onUp 永远轮不到执行。修法：**松手落点判定只收在卡片的
     onUp 一处**（elementFromPoint → stage 则 join，卡则排序），
     圆桌只负责 pointermove 高亮热区。
  3. reorder 先删后插的 off-by-one：`from < to` 时目标索引要 -1，
     否则「把 a 拖到 b 前」变成「挪到 b 后」；after 语义取 over 的
     下一张作为锚点。
- **E2E 视口陷阱**：760px 视口下圆桌 stage 常在视口外，
  `elementFromPoint` 返回 null → 拖入静默失败。测试 helper 必须先
  `scrollIntoView`。（真实产品可在后续阶段补拖动 autoscroll。）

## 网页卡片 Phase 2：真实缩略图 + 原生窗口展开（2026-11-14 下午）

- 卡片身份改为真实 `tabId`：删除本地 `WebCard` 数据，`shared/web-cards.ts`
  只做派生（顺序对账 / presentation / 域名），store 只留 `cardOrder` 与
  `participantTabIds`。关闭卡片 = `closeTab`，收起面板 = park，不销毁页面。
- **最大的技术发现**：`capturePage()` 要求视图真正参与合成——隐藏、0×0、
  放到窗口外都返回空图（"Current display surface not available"）。最终方案是
  透明 `BaseWindow` 采集宿主（opacity 0 / focusable false / ignoreMouseEvents），
  收纳中的标签挂在里面、固定 1280×800；截图时临时 `setVisible(true)`。
  Linux 不支持窗口 opacity，宿主直接禁用。
- 截图链路：`BrowserPreviewService`（debounce 700 / 最小间隔 2s / 并发 1 /
  12 张 LRU / 失败保留旧图）→ 640 宽 JPEG(68) data URL → 独立
  `browser:preview` 通道。标签关闭 `forget` 并广播 clear。
- 拖出/收回：卡片用屏幕坐标 pointerup + `dragProbe` → `detach`；浮窗标题区
  拖动 + 「收回卡片架」→ `recallToShelf` → park。全程只有
  `moveToWindow`，`page.__born` 不变。
- **两个真实缺陷**：① 卡片与标签条都用 `data-tab-id`，`BrowserTabStrip` 的
  `document.querySelector` 先命中架子卡片，排序永远 no-op；改为 `stripRef`
  内查询。② `applyBounds` 在 stage 矩形上又加 40px tabbar，网页整体下沉；
  去掉偏移后 `browser.e2e` 对齐断言恢复。
- 验证：typecheck ✅；build ✅；Vitest **692/692**（53 文件）；全量 E2E
  **64 passed / 8 skipped / 0 failed**。新增 3 条 web-cards E2E、17 条单测。

  需人工过验证）。

## Phase 3：原生窗口拖出与圆桌独立窗口（15:0x–16:0x）

- 根因确诊（拖出不可靠）：渲染层在窗口外收不到可靠 pointer 事件，Phase 2 E2E
  用 `dispatchEvent` 合成事件绕过了 OS 输入链路；另有 float-window `Math.max(0,…)`
  定位钳掉负坐标、浮窗关闭强制 reattach+开面板两个主进程缺陷。尝试 cliclick 做
  OS 级鼠标探针被 macOS 杀掉（exit 137），改用对两种假设都稳健的方案。
- 设计定型：卡片/圆桌拖拽全改 **OS 原生 HTML5 DnD**（dragend 必达 + OS 拖影），
  主进程 `BrowserDragSessionManager` 32ms 轮询 `screen.getCursorScreenPoint` 做
  「窗口外」判定与松手位置（实时光标 > 会话轮询 > 渲染层兜底坐标）；窗口内
  dragover/drop + dropHandled（IPC FIFO 保证先于 dragend）。
- 圆桌：`main/roundtable/`（Service 主进程唯一快照 + WindowManager 唯一实例），
  `#bpRoundtable=` 路由，系统 ✕=归位，`onWindowLost` 兜底，重复 detach 只聚焦；
  草稿改后写者胜出（baseVersion 门控会因键击间隔 < IPC 往返而丢字符）。
- E2E 抓到并修掉 4 个真缺陷：setDraft IPC 返回包装对象致 React 崩溃、圆桌窗口
  关闭后拖拽会话残留挡住后续拖动、窗口被外部销毁状态卡 detached、
  `browser.state()` 是 Promise 不能直接取 `.tabs`。
- 验证：typecheck ✅；build ✅；Vitest **56 文件 731 条**全过（新增 31 条）；
  全量 E2E **65 passed / 8 skipped / 0 failed**（2.1m，无删减）。
