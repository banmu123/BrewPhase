- **移除 AI Workspace 一级入口**（顶栏按钮 + `module==='ai'` 路由），
  底层 ai-chat 服务、MultiAI/Accounts/Conversations 组件、migration 10
  全部保留，等后续阶段以圆桌形式重新接入。ai-workspace.e2e 改为断言
  「入口已移除、圆桌就位」。
- **两个真实 bug 被自己测试抓到**：
  1. `setPointerCapture` 必须在记录起点**之后**、且 try/catch 包裹——
     无 GPU 环境可能抛异常把 `press.current` 赋值一起带走。
  2. **投递竞态**：圆桌与卡片各自挂 document pointerup，卡片 onUp 先
     `setDraggingCard(null)` → React 重渲染把圆桌的 effect 卸掉 →
     圆桌的 onUp 永远轮不到执行。修法：**松手落点判定只收在卡片的
     onUp 一处**（elementFromPoint → stage 则 join，卡则排序），
     圆桌只负责 pointermove 高亮热区。
  3. reorder 先删后插的 off-by-one：`from < to` 时目标索引要 -1，
     否则「把 a 拖到 b 前」变成「挪到 b 后」；after 语义取 over 的
     下一张作为锚点。
- **E2E 视口陷阱**：760px 视口下圆桌 stage 常在视口外，
  `elementFromPoint` 返回 null → 拖入静默失败。测试 helper 必须先
  `scrollIntoView`。（真实产品可在后续阶段补拖动 autoscroll。）

## 网页卡片 Phase 2：真实缩略图 + 原生窗口展开（2026-11-14 下午）

- 卡片身份改为真实 `tabId`：删除本地 `WebCard` 数据，`shared/web-cards.ts`
  只做派生（顺序对账 / presentation / 域名），store 只留 `cardOrder` 与
  `participantTabIds`。关闭卡片 = `closeTab`，收起面板 = park，不销毁页面。
- **最大的技术发现**：`capturePage()` 要求视图真正参与合成——隐藏、0×0、
  放到窗口外都返回空图（"Current display surface not available"）。最终方案是
  透明 `BaseWindow` 采集宿主（opacity 0 / focusable false / ignoreMouseEvents），
  收纳中的标签挂在里面、固定 1280×800；截图时临时 `setVisible(true)`。
  Linux 不支持窗口 opacity，宿主直接禁用。
- 截图链路：`BrowserPreviewService`（debounce 700 / 最小间隔 2s / 并发 1 /
  12 张 LRU / 失败保留旧图）→ 640 宽 JPEG(68) data URL → 独立
  `browser:preview` 通道。标签关闭 `forget` 并广播 clear。
- 拖出/收回：卡片用屏幕坐标 pointerup + `dragProbe` → `detach`；浮窗标题区
  拖动 + 「收回卡片架」→ `recallToShelf` → park。全程只有
  `moveToWindow`，`page.__born` 不变。
- **两个真实缺陷**：① 卡片与标签条都用 `data-tab-id`，`BrowserTabStrip` 的
  `document.querySelector` 先命中架子卡片，排序永远 no-op；改为 `stripRef`
  内查询。② `applyBounds` 在 stage 矩形上又加 40px tabbar，网页整体下沉；
  去掉偏移后 `browser.e2e` 对齐断言恢复。
- 验证：typecheck ✅；build ✅；Vitest **692/692**（53 文件）；全量 E2E
  **64 passed / 8 skipped / 0 failed**。新增 3 条 web-cards E2E、17 条单测。

  真实页面可打开并截到；Claude 停在 Cloudflare 人机验证（真实挑战页截图，

## Phase 3：原生窗口拖出与圆桌独立窗口（15:0x–16:0x）

- 根因确诊（拖出不可靠）：渲染层在窗口外收不到可靠 pointer 事件，Phase 2 E2E
  用 `dispatchEvent` 合成事件绕过了 OS 输入链路；另有 float-window `Math.max(0,…)`
  定位钳掉负坐标、浮窗关闭强制 reattach+开面板两个主进程缺陷。尝试 cliclick 做
  OS 级鼠标探针被 macOS 杀掉（exit 137），改用对两种假设都稳健的方案。
- 设计定型：卡片/圆桌拖拽全改 **OS 原生 HTML5 DnD**（dragend 必达 + OS 拖影），
  主进程 `BrowserDragSessionManager` 32ms 轮询 `screen.getCursorScreenPoint` 做
  「窗口外」判定与松手位置（实时光标 > 会话轮询 > 渲染层兜底坐标）；窗口内
  dragover/drop + dropHandled（IPC FIFO 保证先于 dragend）。
- 圆桌：`main/roundtable/`（Service 主进程唯一快照 + WindowManager 唯一实例），
  `#bpRoundtable=` 路由，系统 ✕=归位，`onWindowLost` 兜底，重复 detach 只聚焦；
  草稿改后写者胜出（baseVersion 门控会因键击间隔 < IPC 往返而丢字符）。
- E2E 抓到并修掉 4 个真缺陷：setDraft IPC 返回包装对象致 React 崩溃、圆桌窗口
  关闭后拖拽会话残留挡住后续拖动、窗口被外部销毁状态卡 detached、
  `browser.state()` 是 Promise 不能直接取 `.tabs`。
- 验证：typecheck ✅；build ✅；Vitest **56 文件 731 条**全过（新增 31 条）；
  全量 E2E **65 passed / 8 skipped / 0 failed**（2.1m，无删减）。

## Phase 4.1：圆桌 Multi-AI 并行问答（20:1x–21:5x）

把 Multi-AI 能力接进圆桌（复用 AIChatService/AgentPageManager/TaskCoordinator，
不造第二套调度），主干改动：

- **广播修正**（规格点名的 bug）：`main/index.ts` 的 aiChat notifier 原来只发
  `getAllWindows()[0]`——浮窗/圆桌窗口加入后顺序漂移，另一个窗口状态卡死。
  改为遍历全部非 destroyed 窗口广播 `aiChat.lastTask()`（带 conversationId）。
- **增量持久化**：ask() 一开始就落 conversation + 用户问题 → 平台一 completed
  立刻写库（notifier 里捎带，persisted Set 去重）→ 任务落定补写剩余终态。
  崩溃/取消不再丢已完成的回答；忙时抛错会撤掉刚建的孤儿 conversation。
  coordinator 改为可注入（构造参数），单测用假 coordinator + 真 SQLite 验证时序。
- **Adapter 加固**：回答基线必须在**点击发送之前**统计（AI 响应快时基线取晚
  会把本轮回答计入旧基线，完成判定永不成立）；写入后校验
  `__bpNormalize(input) === __bpNormalize(prompt)`（textarea 用 value、
  contenteditable 用 innerText），没写进去不点发送（input_write_failed）。
- **测试接缝**：`BREWPHASE_AI_TEST_HOST=127.0.0.1:<port>` 时 homeURL 指向
  `http://<host>/<provider>`、ownsURL 按段匹配路径前缀（/chatgptx 冒不了名，
  端口必须一致）。E2E 用本地夹具页跑真实 probe→submit→poll 全链路，不碰外网。
- **渲染层**：新 `roundtable-ai-store`（task/statuses/error，App 全局订阅，
  两个窗口同态）；RoundtableBody 加平台选择（本地 UI 状态，默认全选，与
  participantTabIds 彻底分开）、开始/停止（不再依赖网页资料参与者）、
  回答区（Markdown 组件、先完成先显示、复制/查看原网页）；占位区加
  任务状态行（独立窗口提问时主窗口也看得到进度）。平台「去登录」用
  可见浏览器 `api.browser.open`（共享 session 回到后台代理页）。
- **innerText 陷阱**（E2E 抓到）：textContent 里的 `\n` 经 innerText 提取时
  被 white-space:normal 折叠成空格——整段变一行，`##` 头还在（整个 heading
  变长）但列表全没了。夹具页必须用 `<br>` 构造换行（富文本渲染本就如此）。
- **极简 Markdown 渲染的级别**：`##` 渲染为 h4（level≤1→h3、2→h4）、列表项
  是 `p.md-ul` 不是 li——断言/样式别按标准 HTML 层级想当然。
- **browser.e2e「拖动与缩放」当前环境必挂**：真指针拖拽（se 手柄 -260,-160）
  只跟到 78px。**stash 后干净 HEAD 455ed71 同样失败**——环境敏感的既有问题
  （无 GPU 帧节流，记忆里同类先例），不是 4.1 回归。已如实记录，不擅自改测试。

## Phase 4.2：真实 WebCard 驱动的圆桌问答（21:0x–22:3x）

架构迁移：参与者从固定 provider 变为**真实 WebCard 的 tabId**。

- **分层**：`ai-chat/adapters/`（types=AIPlatformAdapter 接口 + registry + platform-catalog
  + platforms/chatgpt|claude + host-match）→ `participant-service.ts`（tabId 驱动执行）；
  共享算法抽到 `automation/poll-engine.ts`（probeWithRetry + pollUntilAnswerStable），
  遗留 TaskCoordinator 改调引擎——8 条旧单测全绿证明行为零漂移。
- **旧 automation/adapters.ts 改为转发**（脚本唯一实现在 platforms/），遗留 MultiAI
  路径不变；AgentPageManager 圆桌链路零引用（仅遗留栈保留）。
- **身份链**：Renderer 只传 tabId → isParticipant 校验（RoundtableService.hasParticipant）
  → resolveTabForAI 解析真实 WebContents（实时 url/title）→ Registry 严格主机识别 →
  普通资料/未适配/已销毁页面不参与也不报失败；零可参与明确报错。
- **生命周期**：每轮轮询重新解析 tabId——关页立即 failed(tab closed)、跳出 Adapter 域
  立即 failed；RoundtableService.commit diff added/removed → onParticipantsChanged →
  移出成员 cancelParticipant（run.cancelled=true + 状态）。
- **持久化**：去重键 provider→tabId；metadata 追加 tabId/displayName（旧记录兼容，
  无 schema 变更）；provider 列仍存平台 id。
- **两个真缺陷被 E2E 抓到**：① ParticipantService 构造时没把 params.broadcast 接进
  notify——广播从未发出，主窗口永远看不到进度（shell 靠自身 ask 返回值掩盖了问题）；
  ② cancelParticipant 只改 state 不设 run.cancelled——轮询循环照跑直到超时。
  通知签名改为 `(snapshot) => void`，每次变更带整份快照。
- **Playwright 惰性 locator 陷阱**：`page.locator(...).last()` 在**调用动作时**重新解析，
  三张卡建完后统一 `getAttribute('data-tab-id')` 全拿到最后一张的 id（probe 脚本
  `[ids] tab-3 tab-3 tab-3` 实锤）。必须在每张卡创建后立即取 id。
- platform-catalog 里 Gemini/Grok/DeepSeek **只登记描述符无 adapter**——「已识别·尚未
  适配」是真实状态，不假装能提问（规格 §13 的开放扩展验证）。
