## 换 App 图标：从一张带背景的成品图做出合规的 1024

用户给了一张 AI 生成的图（奶油底 + 咖啡豆 + 环绕圆环），要求换成 iOS 图标，并
「去除多余的背景」。图里除了图案，还有页面底色、瓦片自带的圆角、以及一圈投影。

**处理思路**（不直接裁图，而是「重建背景 + 原样保留图案」）：
1. 量瓦片边界：不能用亮度（页面底 236 vs 瓦片底 241，只差 5），改用量色度特征
   `R − B`（页面 24–28，瓦片 34–43）。四边取中位 → 边距 80px（源图 1254）。
2. 裁成 1254−160 的正方形 → 1024×1024。
3. **背景场**：16×16 网格、只从中间 12%–88% 的格子取中位色（那里绝无投影），
   没采到的格子迭代扩散填平，再双三次放大 → 平滑背景。
4. **图案遮罩**：用图案自身的 `R − B`（底色/投影 ≤ 47，图案 ≥ 62，取 52–68 的带）。
5. 合成 `out = src·α + bg·(1−α)`，α 过 smoothstep 柔化，存 **RGB 无 alpha** 的 PNG。

**踩到的坑**：第一版遮罩用「与背景场的色差」，结果成品上浮出一圈**原图圆角投影的
残影**（像双层圆角）——因为「和背景不一样」对投影同样成立，投影拿到了 α≈0.3 被原样
合成回来了。改用图案自身的色彩特征做遮罩就干净了。这条已写进新建的技能 `ios-app-icon`。

**验收**（资产是二进制，git diff 看不出对错，只能实跑）：
* 图案实心区与源图逐像素比对：色差 mean/p50/p90/p99/max **全为 0**（图案零损失）
* 四角取色是瓦片底色（250,236,215），不是页面色、也不是灰
* 缩到 180/120/80/60/40px 仍认得出
* 装进模拟器 `simctl terminate` 回桌面截图：满幅、系统圆角切得干净、无外圈灰边

另发现：模拟器桌面上有**两个叫 BrewPhase 的 App**——`com.brewphase.app`（旧 bundle id，
CFBundleName 是 "Web"，还是旧图标）与 `com.brewphase.ios`（本工程）。前者是历史遗留的
陈旧安装，没有动它，只报告。

验证：全量 `xcodebuild test` 322 项 0 失败、项目警告 0。

## V2 第一批：数据安全 / Quick Log / Bean Detail

**交付**：`Tools/V2-Batch-1-Report.md`。328 测试 0 失败；干净构建 0 警告；本地化 831 键通过。

**这一批钉住的几条事实与约定**（细节都写进了代码注释与测试）：

* **SwiftData `rollback()` 只撤插入与删除、撤不回既有对象的属性改动**（2026-10 实测，
  `testRollbackDiscardsInsertionsButNotPropertyChanges` 钉住）。所有保存失败路径
  都必须「显式写回」改过的字段：`BeanOriginalValues`（豆子编辑器）、
  `BrewRecorder.apply`（编辑冲煮）、`BeanDetailView`/`StockAdjustView` 手写回。
* 保存失败口径：保留编辑状态 → 明确反馈 → 不 dismiss → 不执行依赖成功的后续。
  App 代码里 `try? context.save()` 已清零（只剩派生数据的日志式处理）。
* 图片三段式：写新文件 → 落库 → 删旧文件。`ImageStore.replace` 已删除（反模式本体），
  孤儿文件靠「清理无用的图片」收尾。
* 持久化容器打不开 → `PersistenceRecoveryView`（**不再退到内存库**）；恢复状态拒绝
  一切写入，不删任何数据库文件。
* 标记喝完/恢复在喝只改 status（`Bean.markFinished/restoreToActive`）：库存与历史
  一律不动；「恢复」保留当前 `remainingG`（但 `isFinished` 仍是 status||剩余=0 的语义）。
* BeanDetail 十层：Hero → Phase → 库存 → 最近一杯（[再记一杯]+展开依据）→ [记一杯] →
  冲煮记录 → 风味变化 → 预计风味窗口 → 知识 → 问一问 → 备注。
* Quick Log：风味标签默认折叠（「添加风味」）；更多参数摘要
  `18g · 1:16 · 92°C · 2:28`；结果页「下一杯建议」加重
  （`BrewDiagnosticCard(emphasizesSuggestion:)` + `TypeScale.emphasis`）。
* 调试通道（simctl 不能点击，沿用 DebugLaunch 惯例）：`run.sh --bean / --bean-action /
  --quick-expand / --stock-overshoot`、`-BrewPhaseScreen persistenceRecovery|stockAdjust`；
  演示库新增第 7 包「已喝完」的豆子（Rwanda Nyungwe，剩 40g，专为「恢复到在喝」）。
* `run.sh` 的空数组在 `set -u` 下会炸（bash 3.2），写法用 `${ARR[@]+"${ARR[@]}"}`。
