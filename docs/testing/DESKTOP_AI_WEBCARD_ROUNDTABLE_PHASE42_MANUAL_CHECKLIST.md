# BrewPhase Desktop — 真实 WebCard 驱动的 AI 圆桌（Phase 4.2）人工验收清单

> 必须在真实桌面 Electron 环境中手工执行。自动化（Vitest / Playwright）使用本地夹具页验证
> 链路、身份与调度，**不能声称真实 AI 平台网页已经通过验证**——真实平台的登录、风控与
> 回答质量只能在这里确认。
>
> 启动开发实例：`cd Desktop && pnpm dev`。

## A. WebCard 身份与识别

- [ ] A1. 打开 chatgpt.com，生成 WebCard，拖入圆桌：成员卡显示「ChatGPT · AI 可参与」（登录后）或「ChatGPT · 需要登录」。
- [ ] A2. 打开 claude.ai，生成 WebCard，拖入圆桌：显示「Claude · …」。
- [ ] A3. 打开 Gemini（gemini.google.com）拖入圆桌：显示「Gemini · 已识别，尚未适配」，开始按钮不把它算作可参与。
- [ ] A4. 打开 GitHub / 普通网页拖入圆桌：显示「网页资料 · 仅供参考」，不会被发送问题。
- [ ] A5. 同一平台开两张 WebCard 拖入圆桌：出现两个独立成员卡（不同 tabId），状态互不影响。
- [ ] A6. 点「重新检测」：成员状态按当前页面实时刷新。

## B. 登录与会话

- [ ] B1. 未登录的 ChatGPT 卡在圆桌内：显示「需要登录」+「去这张卡片登录」；点它会把那张**原始卡片**打开到前台。
- [ ] B2. 在该 WebCard 内手动登录（含人机验证时在真实网页手动通过）→ 点「重新检测」→ 状态变「AI 可参与」。
- [ ] B3. 全程不出现要求 API Key / 账号密码输入的应用内表单；应用不采集凭据。
- [ ] B4. 登录态在应用重启后保持（共享 persist:brewphase-browser 分区）。

## C. 并行问答（核心）

1. [ ] C1. 拖入 ChatGPT + Claude 两张卡（均已登录），输入问题，点「开始讨论」。
2. [ ] C2. 两张卡的原始网页里都出现**同一个问题**（逐字符一致）。
3. [ ] C3. 两平台同时执行（不是串行）；较快的回答先出现在圆桌，不等另一家。
4. [ ] C4. 回答卡显示：平台名 + 卡片标题 + tabId + 状态 + 完整 Markdown 回答。
5. [ ] C5. 「查看原网页」定位到回答所属的**原始卡片**（不是新开的平台页）。
6. [ ] C6. 「复制回答」内容与卡内一致。
7. [ ] C7. 提交不清空草稿；进行中可编辑下一轮问题。
8. [ ] C8. 同平台两张卡分别提问：两份回答独立、不串台，tabId 不同。

## D. 生命周期

- [ ] D1. AI WebCard 拆出为独立浏览器窗口后再提问：回答正常（原始 WebContents 在浮窗中执行）。
- [ ] D2. 卡片收回卡片架（park）后提问：回答正常，登录态不丢。
- [ ] D3. 任务进行中关闭正在执行的 WebCard：对应参与者立即标记失败（tab closed），其他成员不受影响。
- [ ] D4. 任务进行中把 AI 成员移出圆桌：对应任务立即取消，其他成员继续。
- [ ] D5. 页面执行中导航到其它网站：该成员失败（页面跳转离场），不在新页面上继续旧平台脚本。

## E. 双窗口同步

- [ ] E1. 主窗口提问 → 拆出圆桌独立窗口：进度与回答一致。
- [ ] E2. 独立窗口提问 → 主窗口占位区显示「讨论进行中…」→ 完成后「本轮讨论已完成」。
- [ ] E3. 一个窗口取消 → 另一个窗口同步显示已取消；已完成成员的回答保留。
- [ ] E4. 归位后本轮回答仍在；重新拆出仍在。

## F. 历史记录兼容

- [ ] F1. Phase 4.1 时代的旧讨论记录仍能读取（provider 列语义不变）。
- [ ] F2. 新记录里同平台两张卡的回答按 tabId 区分（metadata 内可查）。
- [ ] F3. 任务中途退出应用：已完成成员的回答仍在记录里（问题先行 + 增量落库）。
