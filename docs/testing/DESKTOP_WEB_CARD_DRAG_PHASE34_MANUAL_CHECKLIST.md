# BrewPhase Desktop — Phase 3.4 人工验收清单（卡片拖出 + 添加网页）

自动化只能验证应用内事件链路（合成 DragEvent + 结构断言）；
**真实 OS 鼠标拖动只能在这里验收**。环境：macOS，`pnpm dev`。

排障辅助：拖动时看两处日志——
- 应用窗口 DevTools console：`[drag:card] dragstart / dragend`
- 开发终端：`[drag] begin … / outside=true / release outside … / cancel`
正常链路应依次出现：`dragstart` → `begin webcard/tab-…` → `outside=true`
（光标出窗时）→ `dragend` → `release outside …` → 出现新窗口。
若某一环没出现，把日志贴给开发即可定位。

---

## A. 真实鼠标拖出（本阶段核心验收）

1. 添加 `chatgpt.com`（或任意网页），等缩略图出现。
2. **从缩略图区域按住并拖动** → 卡片被拿起（OS 拖影），拖过主窗口边界，在桌面松手。
   预期：新独立浏览器窗口出现在松手点附近；卡片仍在架上（「独立窗口」）；
   页面未重载。
3. **从标题/域名文字区按住拖动** → 同上。
4. **从卡片中间空白处按住拖动** → 同上。
5. 拖出后在新窗口里：输入文字、滚动、点链接——一切正常。
6. 登录 → 收回卡片架 → 再拖出：**登录态与页面内容都在**。
7. 独立窗口点系统 ✕ → 卡片回到架上（不打开主窗口浏览器面板）。
8. 快速连拖两次同一张卡：第二次只聚焦已有窗口。
9. 拖动中 Esc：拖拽取消，无窗口产生。
10. 拖动后在主窗口内空白处松手：不拆窗；卡片不应被误点开面板。
11. 拖动后紧跟着的那次点击不应打开浏览器面板（若有误开，记录复现步骤）。

## B. 备用入口与排序 / 圆桌

- [ ] 悬浮卡片 → 「独立窗口」小按钮 → 拆出（同一实例，不重载）。
- [ ] 拖卡片到另一张卡上松手 → 只排序，不拆窗。
- [ ] 拖卡片进圆桌热区松手 → 加入参与者，不拆窗。
- [ ] 悬浮时左上角出现低调 ⠿ 握把；按钮区不挡拖动。

## C. 添加网页编辑卡

- [ ] 点击「添加网页」→ 编辑卡出现，输入框**自动聚焦**。
- [ ] 粘贴完整网址 → 点击「打开网页」→ 卡片正常生成、缩略图出现。
- [ ] 输入网址按 **Enter** → 同上。
- [ ] 空输入时「打开网页」禁用。
- [ ] 提交过程中按钮显示「正在打开…」且不能重复提交。
- [ ] 输入 `ftp://example.com` → 表单内出现错误提示，取消后无残留空白卡。
- [ ] 输入合法但连不上的地址 → 卡片显示「加载失败」（不是表单内报错，属预期分层）。
- [ ] **Esc 取消** → 编辑卡消失，不留空白卡片。
- [ ] 深色主题下：文字/输入框/错误行/按钮对比度正常。
- [ ] 窄窗口（<900px）：编辑卡自适应，不溢出、不遮圆桌。

## D. 回归确认（不许回退）

- [ ] 圆桌标题栏拖出仍正常（用户已验收的能力不回退）。
- [ ] 圆桌手柄拖回占位区归位、「归位」按钮、系统 ✕ 归位——三条路径都好。
- [ ] 两类独立窗口（网页 + 圆桌）可同时存在。
- [ ] 点击卡片（非拖动）仍在主窗口打开浏览器面板。

## 已知边界

- 自动化环境无法注入 OS 级鼠标（cliclick 被 macOS 拦截），真实拖动只能人工验收；
  E2E 覆盖的是合成事件链路 + 拖拽面结构断言，不能写成「真实 OS 拖拽已通过」。
- 拖动释放到**圆桌独立窗口**上时按「窗口外」处理（会拆出浏览器窗口）——
  这是当前定义的合理行为，若希望改为「忽略」，另开阶段讨论。
