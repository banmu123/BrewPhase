# BrewPhase Desktop — AI 圆桌多平台并行问答（Phase 4.1）人工验收清单

> 必须在真实桌面 Electron 环境中手工执行。自动化（Vitest / Playwright）使用本地夹具页验证链路与双窗口同步，
> **不冒充真实 AI 网页端的结论**——真实平台的登录、风控与回答质量只能在这里确认。
>
> 启动开发实例：`cd Desktop && pnpm dev`（另开一个终端；E2E 与 dev 不能同时跑模拟器抢占无碍，但人工验收请单独跑）。

## A. 登录验收

- [ ] A1. 打开 BrewPhase → Studio Home → 圆桌。两个平台卡显示「页面未打开」，下方出现「GPT 去登录」「Claude 去登录」。
- [ ] A2. 点「GPT 去登录」：内置浏览器面板打开 chatgpt.com；手动完成登录（含人机验证时在真实网页里手动通过——应用不采集凭据、不绕过风控）。
- [ ] A3. 回到圆桌点「重新检测」：后台代理页尚未建立时仍可能显示「页面未打开」；首次提问后状态转为「已登录」。
- [ ] A4. 未登录直接提问：任务状态显示「需要登录」，不伪造回答，另一平台不受影响。
- [ ] A5. 点「Claude 去登录」：同样完成 claude.ai 登录（注意 Cloudflare 挑战页需人工通过）。
- [ ] A6. 登录一次后重启应用再提问：登录态保持（共享 `persist:brewphase-browser` 分区）。

## B. 并行提问验收（核心）

1. [ ] B1. 开启 BrewPhase，圆桌选择 ChatGPT 和 Claude（默认已选）。
2. [ ] B2. 输入同一个问题（多行问题亦可），点击「开始讨论」。
3. [ ] B3. 打开任务管理器或观察两块平台卡：两个平台同时进入「检查页面 → 发送中 → 正在生成」，**不是**一个完成才启动另一个。
4. [ ] B4. 到 ChatGPT 网页端确认收到的文本与输入框中的问题完全一致（逐字符，含换行）。
5. [ ] B5. 到 Claude 网页端做同样确认。
6. [ ] B6. 较快的平台（通常 ChatGPT）完成后，其回答**立即**出现在圆桌回答区，不等另一家。
7. [ ] B7. 另一家生成期间，已完成回答卡不被覆盖、不闪烁消失。
8. [ ] B8. 两块回答卡最终内容完整，Markdown（标题 / 列表 / 表格 / 代码块）渲染正常，无串台（GPT 卡里没有 Claude 的内容，反之亦然）。
9. [ ] B9. 「复制回答」粘贴出的文本与卡内一致；「查看原网页」在浏览器面板打开对应平台会话。
10. [ ] B10. 提交成功后输入框草稿**不被清空**，可继续编辑下一轮问题。

## C. 窗口同步验收

1. [ ] C1. 主窗口圆桌提问；拆出为独立窗口：回答与进行中状态原样出现在独立窗口。
2. [ ] C2. 独立窗口里发起新提问：主窗口占位区出现「讨论进行中…」，完成后转为「本轮讨论已完成」。
3. [ ] C3. 任务进行中在一个窗口点「停止」：另一个窗口同步显示「已取消」；已完成的平台回答保留。
4. [ ] C4. 关闭其中一侧窗口（主窗口或圆桌窗口），另一侧不报错、任务照常推进。
5. [ ] C5. 圆桌归位后本轮回答仍在；重新拆出仍在。
6. [ ] C6. 双向快速连续提交：第二窗提交被拒（忙碌提示），不会产生两个并行任务。

## D. 异常场景

- [ ] D1. ChatGPT 未登录、Claude 已登录：仅 GPT 卡显示「需要登录」，Claude 正常返回。
- [ ] D2. 断网后提问：平台卡显示失败原因（打开页面失败 / 页面无法操作），不伪装成功。
- [ ] D3. 长时间不回答（>180s）：显示「等待超时」。
- [ ] D4. 平台改版导致找不到输入框：显示「页面无法操作」，另一平台不受影响。
- [ ] D5. 任务中途强制退出应用再启动：已完成的平台回答仍在讨论记录里（问题先行 + 增量落库）。

## E. 原有能力回归

- [ ] E1. 网页卡片拖入圆桌 / 移除 / 排序照旧；关闭卡片自动摘除参与者。
- [ ] E2. 圆桌标题栏拖出 / 归位 / 系统 ✕=归位，参与者与草稿不丢。
- [ ] E3. 网页卡片拖出独立窗口、收回卡片架照旧。
- [ ] E4. 中英双语切换：新增文案（平台选择 / 开始讨论 / 本轮讨论等）都跟随语言。
