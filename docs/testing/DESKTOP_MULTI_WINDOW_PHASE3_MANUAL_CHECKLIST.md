# BrewPhase Desktop — Phase 3 人工验收清单（多窗口工作空间）

自动化已覆盖：拖拽会话状态机、松手位置裁定、拆出/收回链路、关闭语义、跨窗口同步、
负坐标几何算法（合成事件 + 主进程假光标走完整 IPC 链路）。下面这些**只能在真实
鼠标 / 真实系统窗口 / 真实多显示器**下确认，CI 不代替。

环境：macOS（主验收）或 Windows；`pnpm dev` 或安装包；中英文各过一遍。
前置：`pnpm dev` 启动桌面端；准备一个能登录的 AI 站点账号（如 ChatGPT）。

---

## A. 网页卡片：真实鼠标拖出（OS 级）

1. Studio Home →「添加网页」→ 输入 `chatgpt.com` → 等卡片出现真实缩略图。
2. **按住卡片中部，用真实鼠标拖过主窗口边缘，在桌面（窗口外）松手**。
   预期：
   - 按下后拖动，OS 拖影（卡片缩略图）跟随光标，**越过窗口边界后拖影仍可见**；
   - 松手后出现新的 BrewPhase 浏览器窗口，位置贴近松手点；
   - 窗口有品牌标题栏、标签条、地址栏/后退/前进/刷新；
   - 页面**没有重新加载**（滚动位置、已输入内容不变）；
   - 原卡片仍在架上，chip 显示「独立窗口」。
3. 在主窗口内拖动卡片到另一张卡片上松手 → 只排序，**不**开新窗口。
4. 拖动到圆桌热区松手 → 卡片加入圆桌，不开新窗口。
5. 拖动中按 **Esc** → 拖拽取消，无任何窗口产生，卡片原位。
6. 快速连拖两次同一张卡到窗口外 → 第二次只聚焦已有窗口，不出现两个浏览器窗口。

## B. 独立浏览器窗口与收回

- [ ] 拖动系统标题栏移动窗口；拖边缘/四角缩放；最小化 / 最大化 / 恢复可用；最小尺寸 560×420。
- [ ] 在独立窗口里正常浏览：点链接、输入文字、滚动。
- [ ] **登录 ChatGPT** → 点「收回卡片架」→ 窗口关闭、卡片回到缩略态、缩略图更新。
- [ ] 再点卡片展开 / 再拖出 → **仍是登录态、原对话**（会话不丢）。
- [ ] 再次拖出后，点窗口的**系统关闭按钮（红绿灯 ✕）** → 卡片回到架上（已收纳），
      **主窗口不弹出浏览器面板**，页面未销毁（再展开内容还在）。
- [ ] 卡片架上的 ✕ 才是真正关闭：点击后卡片消失，WebContents 销毁。

## C. 多显示器（有第二块屏幕才测；无屏跳过并如实记录）

排列逐项验证（系统设置里切换排列后重测）：

- [ ] **A：副屏在右**——把卡片/圆桌拖到副屏松手，窗口出现在副屏松手点附近。
- [ ] **B：副屏在左**（副屏坐标为负）——同上；窗口绝不跳回主屏（这是 Phase 3 修的缺陷）。
- [ ] **C：副屏在上**（副屏 y 为负）——同上。
- [ ] **D：不同 DPI**（主屏 1x、副屏 2x）——窗口尺寸正常、无错位；拖回主窗口落点正确。
- [ ] 窗口拖到两屏交界处松手：窗口完整可见，不出屏。
- [ ] **拔掉副屏**（窗口在那块屏上）：圆桌/浏览器窗口回到仍可见的屏幕（macOS 会自行
      归位或由 workArea 兜底）；应用不崩溃，卡片/圆桌状态不丢。

## D. AI 圆桌：拆出为独立窗口

1. 拖两张卡片进圆桌 → 参与者 2 位。
2. **拖动停靠圆桌的标题栏（整块圆桌会作为拖影），拖出主窗口边界松手**。
   预期：新的「AI 圆桌」窗口出现在松手点附近；主窗口圆桌位置变成占位区
   （人数 + 参与者名 + 重新打开 + 归位）；Studio Home 其余内容可正常使用。
3. 点「独立窗口」按钮 → 同样拆出（键盘/触控板路径）。
4. 独立圆桌窗口：
   - [ ] 标题栏拖动可移动窗口；边缘可缩放（最小 460×340）；归位按钮可用。
   - [ ] 参与者缩略图与主窗口一致；提问输入可用。
   - [ ] **拖回手柄（标题栏左侧 ⠿）拖到主窗口占位区松手** → 归位，参与者与草稿保留。
   - [ ] 点「归位」按钮 → 同效。
   - [ ] 点系统 ✕ → 窗口关闭 = 归位（数据不丢，主窗口恢复停靠圆桌）。
   - [ ] 再拆出 → 窗口里参与者、草稿与归位前一致。
5. 跨窗口同步（两屏或同屏并排都行）：
   - [ ] 主窗口改草稿 → 独立圆桌窗口同步显示；
   - [ ] 独立窗口改草稿 → 归位后主窗口输入框显示同一份；
   - [ ] 独立窗口里移除参与者 → 主窗口占位区人数立即减少；
   - [ ] 主窗口关闭卡片 → 两边参与者同步摘除。

## 已知限制（如实记录，不算失败）

- 圆桌拆出的 OS 拖影是**整块停靠圆桌的快照**（macOS 原生渲染，半透明），不是实时画面。
- 独立圆桌窗口与主窗口的 UI 是同一份 React 代码、两个 Renderer；主窗口占位区不显示草稿内容（只显示人数与参与者名）。
- 自动化无法产生真实 OS 拖拽：E2E 用合成 DragEvent + 主进程假光标走完整链路（真实光标轮询路径相同）；真实鼠标手感以本清单为准。
- Claude 首次访问停在 Cloudflare 人机验证：卡片显示的是挑战页的真实截图，人工通过后缩略图才会更新。
